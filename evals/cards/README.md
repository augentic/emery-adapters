# Eval cards

The record of the scorecards the eval runner (`cargo run -p evals`, [evals/README.md](../README.md)) wrote under `target/eval/`. A card is one dated run of the eval over the cases named in its headings, recording the model, the number of runs a case, and — per run — the exit code, the wall time, the completions the run opened with their tokens, the requirement and criterion recall against the case's `expected.toml`, the stems, and the misses by anchor. `target/` is gitignored and `make sweep` drops what sits there untouched for a week, so no card is in the tree: a card a decision rested on was committed beside this file, never edited, until its decision was written, and is read from history at the commit [the index](#rounds) names; a later card's figures were read into its round as they stood under `target/eval/`, and the round is its record. Completed programme files are archived in git history at the commit their rows name (`git show <commit>:evals/cards/<programme>.md`); what stays in the working tree is this README and the active programme files.

The `emery` and component (`typescript.wasm`, `python.wasm`) paths a card's header cites are the build the run used — a Cursor sandbox cache of this tree's `cargo-target`, not a path this repository holds — and say nothing beyond which binary answered.

## Protocol

Every round follows one protocol, and the rounds that ran it are where its rules were learned.

- **Predictions first, then the rule, then the runs.** The predictions and the decision rule are written into the round's file before an arm is built, each arm is three runs under a pinned `CURSOR_MODEL`, and the card's figures are read into it against the rule — the result column and the decision — rather than the card kept beside it. An expectation moves only where the code's own rule, checked against the anchor and stem rules, says the expectation was wrong, and the move is recorded with the card.
- **A rule is written on the near-deterministic columns.** Surfaces by entry, stems, the refused claims and corrected seams, the correction rounds of the survey turn, and the rung a run landed on are decided by code or by the model's one reading of a convention, and they held or moved exactly on every arm so far. Recall is the model's naming of behaviours run to run: one component's own spread over six runs on `fastapi-template` was 29–35 of 36, wider than any arm's effect in the loop round, so three runs cannot tell a one-requirement difference from noise and a rule never turns on recall alone — it is read as a band, and a clause on it says "within the band", never "greater than".
- **"No run fails" reads "before grading".** A run the backend refuses before any claim is accepted is the host's failure, and the runner puts it again once. A run that fails after its claims are accepted — in the engine's own turns — is graded on them and the engine's failure is recorded against the engine, not the arm; the card names the turn it died in.
- **An off arm is built from a worktree.** A rule under test has no feature flag, so its off arm is a local edit to the one function named, built from a detached worktree ([evals/README.md](../README.md) has the commands), run, and never shipped; the working tree never holds the off state, which the loop round learned when an in-flight arm edit was swept into an unrelated commit.
- **A card is read back to its anchors.** The runner stages every run under `target/eval/<card>/<case>/`, so a card's `run-N.evidence-*.json` and `run-N.facts.md` outlive the next invocation and a second clause — where the matched requirements landed, which the misses-by-anchor cannot show — is read from the card's `requirement anchors` line rather than from three more runs.
- **An omnia card was a pair through Round M, and is now single-arm.** From Round F through Round M (`e8069e4:evals/cards/omnia.md`), every omnia build card ran twice over one component: under `emery` and `composer-2.5` (the large-model arm) and under `emery-dev` and `openai::Qwen/Qwen3-Coder-Next-FP8` on a RunPod H200 ([evals/README.md](../README.md#the-small-model-arm)). With the untrained ladder's stop rule firing at Round M (`f552e13`), the pairing is retired: `omnia` rounds run under `emery` and `composer-2.5` alone, and the small-model recipe is used when evaluating fine-tuned checkpoints.
- **A target card is a `--rebuild`.** The first build card over a case is `--build`, which seals a revision and builds it; every target card after it is `--rebuild <that card> --target <name>`, which copies the card's staged project, clones the repository its run sealed into at the `Revision` root alone, with no label, and builds the same sealed revision again under this invocation's binary, component, model, and width, so one plan is built under each target and the plan's own variance is out of the comparison.
- **A denial reading is `file-*` and `network-*` alone.** The kernel boundary's refusals are read from macOS's unified log over the run's window (`log show --start … --end … --predicate 'eventMessage CONTAINS "deny"' --style compact`), filtered to the bridges' and their tools' pids, and read for the `file-read-*`, `file-write-*`, and `network-outbound` kinds, each by its path or host: a toolchain under `$HOME` the target's worker grant does not name is a root for the adapter's `grants` to spell, a tool's walk up from the lend is the fence doing its work, a system path is the profile's and a finding.

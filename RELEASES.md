## 0.13.0

Unreleased

### Changed

- Adapters are guests of the `source-adapter` world, written the way every omnia guest is (engine `emery-sdk` 0.38): `src/guest.rs` implements `emery_sdk::export::Guest` on a unit type for `wasm32` alone — `metadata` answers `emery_sdk::export::metadata(KIND)`, and `extract` lifts the input, calls the crate's `survey`, and hands the seams to `emery_sdk::mine`, which runs one gated turn per seam over `Context { adapter_id, input }` and the embedded `prompts/extract.md` and joins the answers. `src/lib.rs` is `pub const KIND`, `emery_sdk::registry!()` as `docs`, and the module declarations; `src/survey.rs` is the one fn with logic of its own, a plain fn over the `SourceContent` when it asks nothing. There is no `SourceAdapter` trait, no `source!` macro, no `src/operations.rs`, and no `export` feature: the guest module is `cfg(target_arch = "wasm32")` in each crate. `EvidenceTurn`, the free `evidence`, `content_note`, `registry::body`, and the SDK's `types` module are gone with the earlier shape; the SDK re-exports the contract's types at its root and omnia's `model` module. The five probes under `crates/test-programs/programs/probe/` are `Guest` impls the same way.
- The live examples are the `emery.toml` configs alone: each binds the shipped component `make release` builds (`target/wasm32-wasip2/release/<name>.wasm`) rather than a root-package `[[example]]` cdylib of its own, so the root package has no wasm32 dev-dependencies and `examples/<name>/lib.rs` is gone.
- Every adapter states its seams through its `survey` and hands them to `emery_sdk::mine`, so every model call goes through the SDK's fan-out and join. `documentation` cuts a tree into one `Seam::Files` per top-level directory of at least two documents — each lent its own directory — with the root's own documents and every smaller directory as one more; `typescript` cuts the same way over production source alone (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`; never `node_modules`, `vendor`, `target`, `dist`, `build`, `tests`, `__tests__`, dot entries, declaration files, or `*.test.*` / `*.spec.*`) into one `Seam::Note` per group that lends the whole root and names the modules the call mines, so imports and `tsconfig.json` resolve; `intent`'s one seam moves into `survey`. Both walks go through `emery_sdk::survey`, which prunes `spec.md`, `design.md`, and `.omnia/` wherever they appear. A tree that cuts into fewer than two groups, and an inline value, stay one `Seam::Whole` — a single call, as before — so the example fixtures and the component suites are unchanged. On a tree that does split, claim order changes once: `REQ-nnn` renumbers on the project's next `specify`.
- `documentation`'s and `typescript`'s prompts describe the seam a call is given — the whole tree, or the files the message lists beneath `$SOURCE_DIR` — and steer ids to lead with the domain noun of that seam, so two calls over one tree do not name one requirement twice; `typescript`'s reads beyond the listed modules only to resolve what they reach.
- `typescript` surveys by model: on a tree of several directories it asks the model once, under its new `prose/prompts/survey.md`, to group the production modules by the externally visible surface they serve — a route, a command, a job, an exported API — through `emery_sdk::survey::by_model`, which lists the candidates, lends the root, checks the answer (a module never offered, in two groups, or an empty group goes back as findings), and folds every group under the floor with every module the model left out into one remainder; each group becomes one `Seam::Note` as before, so imports and `tsconfig.json` still resolve. Grouping by surface replaces the cut by directory, which split every route from its service; the remainder is the SDK's, so coverage stays total. A tree no directory cut would split, and an inline value, stay one `Seam::Whole` with no survey turn spent, so the example fixtures and the component suites are unchanged. A survey that asks the model is an `async fn survey<P: Model>(model, ctx)`; `documentation`'s and `intent`'s, which ask nothing, are plain fns over the `SourceContent`; a second prompt, `prompts/survey.md`, is held by `tests/prose.rs` to the same cap with a worked example that parses as `survey::Partition`, and `typescript` requires it embedded.
- `sources/<name>/tests/survey.rs` asserts the survey natively: how a tree cuts, what it leaves out, and when it stays whole — as plain tests with no model for `documentation` and `intent`; `typescript`'s scripts a partition over `omnia_test::guest::Scripted` and asserts the candidates it offered, the notes it cut, and that its bound tree spends no turn.
- The component suites gain the `fanout` probe and `probe_fanout`: a fixture adapter that mines two `Seam::Note` seams, run over the support's `Barrier` — a `ScriptedModel` that answers a completion only once a party of them is pending and fails it after a bounded hold otherwise. It guards the host property the SDK's fan-out rests on, that the completions one guest issues together are pending together; `support::run` now takes any `Strict` host model rather than `ScriptedModel` alone.
- Adapters declare `const KIND: SourceKind` (`emery_sdk::SourceKind`, formerly `Authority`) — the kind of source they read; "authority" now names only the precedence those kinds rank by.
- The kind of source rides the component's `metadata`, not its Evidence: `emery_sdk::export::metadata(KIND)` reports it beside the `emery-version` pin, the engine reads it once at load and ranks every document the adapter returns by it, and the Evidence a component returns is claims alone (the WIT `evidence` record and the SDK's `Evidence` lose `kind`; a document-level `kind` in a model answer is a schema miss the backend corrects). `emery_sdk::Answer` is gone with it — `tests/prose.rs` parses each worked example as `Evidence` directly — and the driver's `echoed` mode proves the kind the probe declares crosses the bindings through `metadata`.
- Cut to extract-only (ADR-0008 / ADR-0009): each source adapter exports `extract` + `metadata` only. Survey prompts, the target axis (`vectis`, `omnia`, `contracts`), and the extra extract sources (`captures`, `screenshots`) are deleted from the live tree — retrieve them at tag `v1`.
- Adapter code names one engine crate, `emery_sdk::`: the contract types, the prose registry (`emery_sdk::Doc`, `emery_sdk::registry!()`), and, for the driver programs, the `Source` capability are all re-exported by the SDK. Until an engine release tag carries that SDK, `[patch.crates-io]` fetches `augentic/emery` by git (path patches stay commented for sibling co-development).
- The embedded prose registry lives in the engine's `emery-prose` crate and reaches an adapter through the SDK: adapters call `emery_sdk::registry!()` and name `emery_sdk::Doc`; `emery-prose` itself is each adapter's `[build-dependencies]` entry alone, with the `emit` feature for the walker. The WIT contract lives in the `emery-adapter` contract crate, named for the `emery:adapter` package, as its `source` axis module; the SDK re-exports it, `Source` included, so nothing in this workspace depends on `emery-adapter` — the `crates/test-programs` driver guest calls adapters through `emery_sdk::Source`.
- Adapters depend on `emery-sdk` (the adapter SDK's new name) alone — `[dependencies]` is that one crate: `emery_sdk::export::{Guest, …}` in the guest module, `use emery_sdk::{Context, Seam, Evidence, Error, Model, …}` everywhere else. There is no `emery-source` crate.
- The graded live eval is a public-contract client of the shipped `emery` binary — one `specify` per case over the built components, `emery show spec` for grading, a dated scorecard — operator-invoked, never CI. Its `examples/eval` runner and `make eval` are removed from the tree pending recreation as a root example beside `examples/<name>/`, whose configs it will drive as its cases.
- The component rung is rebuilt on omnia's `test-programs` pattern. `crates/test-programs` replaces `examples/caller` and `examples/conformance`: its `build.rs` runs one `omnia_test::build::Components` build into one `gen.rs` — every `sources/*` component as `ADAPTER_<NAME>` + `foreach_adapter!`, every `programs/<group>/<scenario>.rs` guest program as `<GROUP>_<SCENARIO>` + `foreach_<group>!`. The one driver (`source/extract`: `metadata`, then `extract` in the mode its arguments name — none: both `SourceInput` arms expecting gated evidence; `refused <code>`: expecting that Omnia refusal class; `echoed`: expecting the helpers' `maximal()` evidence field for field) and the fixture adapters standing in for the one under test (`probe/refusing`, `probe/upstream`, one per WIT `error` arm; `probe/echo`, answering `maximal()` without a model call; `probe/gated`, an inline corpus over `Seam::Whole`) are programs. Host suites are the root package's: `tests/source.rs` (`foreach_adapter!`, every shipped component — `metadata` opens no completion, each `extract`'s system prompt is the embedded `prompts/extract.md`), `tests/probe.rs` (`foreach_probe!` — the error arms, the lowering of every record field, and, once over `gated`, the SDK's request shape, reference tools, lend, and spent-budget refusal under the runtime), and `tests/prose.rs` (`foreach_adapter!` — the prompt embedded and under the 800 non-blank-line cap, its `## Worked example` fence gate-valid under the adapter's source kind; absorbs the per-adapter `tests/registry.rs`, whose reference-presence checks the embed-time walker already makes). The two component suites share one runner (`tests/support/mod.rs`). The root is now the `emery-adapters` package over `crates/*` + `sources/*`, so the shared CI workflow and `make test` run `cargo nextest run --workspace` (the root alone would skip every adapter's suite); the per-adapter `tests/operations.rs` is `tests/survey.rs`, trimmed to what the adapter itself decides — no prompt-phrase or SDK-brief pins. The guest side — every program and the adapters' `guest` modules — lints for `wasm32-wasip2` with the clippy command in `AGENTS.md`, which native clippy compiles to nothing. Debug builds optimise the Cranelift JIT so the component suites compile every component in seconds rather than minutes.

### Requires

- Engine revision whose `emery-sdk` is the helper shape — `mine`, `survey`, `export::{Guest, metadata}` — and re-exports the contract's `Source` capability and the prose registry (`Doc`, `registry`, `registry!`) beside the extract-only `emery-prose` (the git pin in the root `Cargo.toml`, currently emery `main`). The first adapter train publish waits on an engine release tag.

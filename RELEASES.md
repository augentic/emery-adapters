Discovery by parsing replaces the survey by model that preceded it — one `survey.md` turn per tree, held to the tree by `emery_sdk::survey::surfaces` — and, before that, the cut by directory, which split every route from its service, and the grouping by surface, which asked the model to walk each surface's modules before any was mined. `prose/survey.md` is deleted, `emery_sdk::survey` with it (engine `emery-sdk` 0.38), and no adapter puts the model to anything but a seam's turn: a survey is `pub fn survey(input: &SourceInput) -> Result<Survey, Error>`, called from the guest's `extract` as `survey::survey(ctx.input)?`, where `Survey { seams, types }` is the seams to mine and the `type` claims to join. What a run mines is the same on every run, the prompt tells the model how to read what code found rather than how to find it, and the component suite asserts the survey's decisions with no inventory scripted.
- An adapter has no tests of its own: its `survey` is guest code, declared in `src/lib.rs` for `wasm32` alone beside the `mod guest`, and the crate exports `PROSE` and nothing else, with no dev-dependencies. What the adapter decides is asserted in the root `tests/source.rs` through what the host sees of the built component under the runtime — one completion per seam the survey chose, each carrying the seam's data: the files a seam lists (`documentation_directories`), the brief `intent` read through the mount with the engine's own files staged beside it, the surface lines, boundaries, and packages `typescript` lays — and its refusals through the driver's `refused <code> [<value>]` mode, which now takes an inline value too (`intent_not_one_file`, `intent_empty_brief`, `typescript_no_module`); what an adapter joins to the answer from its own reading of the source — `typescript`'s parsed `type` claims — through the driver's `types <name>..` mode (`typescript_types`). Nothing pins the SDK's brief text. `make lint` runs a second clippy pass for `wasm32-wasip2` over the guest side, which native clippy compiles to nothing.
- The component suites gain the `fanout` probe and `probe_fanout`: a fixture adapter that mines two `Seam::note(..)` seams, run over the support's `Barrier` — a `ScriptedModel` that answers a completion only once a party of them is pending and fails it after a bounded hold otherwise. It guards the host property the SDK's fan-out rests on, that the completions one guest issues together are pending together; `support::run` now takes any `Strict` host model rather than `ScriptedModel` alone.
- The driver gains a `together` mode, and the probe suite `fanout_together`: two `extract`s over the lent workspace dispatched at once from one caller, as the engine dispatches one per source, run over the `fanout` probe behind a `Barrier` of four. It guards the host property the engine's fan-out over sources rests on: the link dispatches one caller issues together run together, so the completions each opens are all pending before any is answered. The `Barrier` fails every completion after a hold expires, so the SDK's retry of a seam that failed upstream cannot fill a party late and pass either guard. `test-programs` depends on `futures` for `wasm32`.
- The references every adapter shares are the SDK's. `codex/references/runtime/` and each adapter's `prose/references/emery-runtime` symlink are gone: `claims.md` and `reconciliation.md` are embedded once in the engine's `emery-sdk` as `emery_sdk::RUNTIME` (`claims.md`, `reconciliation.md`), shipped with the SDK an adapter compiles against, so the prose that describes the claim gate moves with the code that enforces it. `read_doc` answers them after the adapter's own table while `list_docs` omits the claim rules the system carries, so the prompts link `claims.md` and `reconciliation.md` — as if they sat beside the prompt at the `prose/` root — where they linked `../references/emery-runtime/…`, and no `PROSE` lists them — `documentation`'s and `intent`'s lists are their one prompt. the root `tests/prose.rs` passes `RUNTIME` to `emery_sdk::check` as the imports, which accepts those two link targets, requires neither in the tree, and refuses a listed document at either path, which would shadow the SDK's; the bundle's contributor README goes with the bundle, its editing rules now [CONTRIBUTING.md § Prompt authoring](CONTRIBUTING.md#prompt-authoring)'s one line — link a shared rule, never restate it.
- `PROSE` is a flat list of file paths: `emery_sdk::prose!["../prose/extract.md", ..]`, each document named from `src/lib.rs` the way `include_str!` names a file, and tabled by what follows its `prose/` segment, so `read_doc` and `check` know it as `extract.md`. There is no separate root argument, and a listed file outside a `prose/` directory fails the build at the list. The `prose/` tree is flat at its root: `extract.md` sits beside `references/` rather than under a `prompts/` wrapper of their own, so a prompt links its references as `references/<doc>.md` and the SDK's as `claims.md`.
- Each component embeds only what a prompt tells the model to read. `documentation`'s `prose/rules/documentation-verbatim-preservation.md`, a v1 review rule no prompt linked, is deleted with its `rules/` directory; the prompt itself states the verbatim rule. The root `tests/prose.rs` names each adapter's one prompt, `extract.md`, to `emery_sdk::check`, which now refuses a prompt the table lacks and a listed document no prompt reaches through relative links, so a document the model is never told to read cannot ship again.
- `typescript`'s reference corpus is rewritten for the claim contract its prompt teaches, and cut from about 2,700 non-blank lines to under 500. Gone: `lessons-learned.md` (a retrospective on the v1 skill, whose durable rules were already the other references' and stay there), `semantic-search.md` (a tooling proposal with install steps), `language-mapping.md` (a TypeScript-to-Rust porting cheatsheet in the v1 artifact format, with decorator guides for languages this adapter never reads), `design-template.md` (a fourteen-section v1 design layout the engine's six-section design never fills), and `context-gaps.md`, whose what-to-capture guidance folds into the references that remain. The five "Step" documents lose their THINK / ANALYZE / VERIFY procedure, tag scheme, and v1 artifact renderings, and what they taught — the manifest, where each kind of surface enters, the entry layer, what a `requirement` captures from a handler, `type` declarations (since the parser's to copy), outbound HTTP and the stores, brokers, caches, and identity providers a client reaches as `call` claims, emitted telemetry, and the checklist — is sections of `extract.md` keyed to the claims they feed. The three worked examples now show the Evidence the extract call answers with — a `## Evidence` JSON fence of claims, in the shape of the prompt's own worked example — in place of a v1 Markdown artifact, and the prompt's `callee` rule names a package import (`<package>:<symbol>`) and a global (`fetch`) beside a symbol of the tree. The root `tests/prose.rs` parses every `## Evidence` fence under `references/examples/` as `Evidence` and holds it to the claim gate, as it does the prompt's worked example, so an example cannot teach a shape the adapter would refuse.
- The WIT `input.key` is `input.name` (engine `emery:adapter` with `SourceInput.name`): the name the specification cites the source by — the operator's `[[source]] name`, the adapter's name when omitted — which the adapters read as `ctx.input.name` and whose prompts call the "source name". A component built against the `key` shape does not instantiate under an engine of this revision, and one from this tree does not instantiate under an earlier engine.
- Adapters name their `emery_sdk::SourceKind` (formerly `Authority`) — the kind of source they read — in their `metadata` answer; "authority" now names only the precedence those kinds rank by.
- The kind of source rides the component's `metadata`, not its Evidence: `emery_sdk::metadata(kind)` reports it beside the `emery-version` pin, the engine reads it once at load and ranks every document the adapter returns by it, and the Evidence a component returns is claims alone (the WIT `evidence` record and the SDK's `Evidence` lose `kind`; a document-level `kind` in a model answer is a schema miss the backend corrects). `emery_sdk::Answer` is gone with it — `tests/prose.rs` parses each worked example as `Evidence` directly — and the driver's `echoed` mode proves the kind the probe declares crosses the bindings through `metadata`.
- Cut to extract-only (ADR-0008 / ADR-0009): each source adapter exports `extract` + `metadata` only. Survey prompts, the target axis (`vectis`, `omnia`, `contracts`), and the extra extract sources (`captures`, `screenshots`) are deleted from the live tree — retrieve them at tag `v1`.
- Adapter code names one engine crate, `emery_sdk::`: the contract types, the embedded prose (`emery_sdk::Doc`, `emery_sdk::prose!`, the `emery_sdk::body` / `emery_sdk::find` lookups and `emery_sdk::check`), and, for the driver programs, the `Source` capability are all re-exported by the SDK. Until an engine release tag carries that SDK, `[patch.crates-io]` fetches `augentic/emery` by git (path patches stay commented for sibling co-development).
- The embedded prose lives in the engine's `emery-prose` crate and reaches an adapter through the SDK: the crate lists its tree as `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its root (the `registry!` macro's new name and shape, after `include_str!`: each document named from the invoking file, tabled by what follows its `prose/` segment, and the expansion is the table itself, every body an `include_str!`), and the root `tests/prose.rs` holds each list to its tree with `emery_sdk::check` — every document under `prose/` listed once, every relative link a listed document or one of the SDK's runtime references — so the root package names each adapter crate as a native dev-dependency and reads the prompts from the table; an adapter has no `[build-dependencies]` and no `build.rs`. The WIT contract lives in the `emery-adapter` contract crate, named for the `emery:adapter` package, as its `source` axis module; the SDK re-exports it, `Source` included, so nothing in this workspace depends on `emery-adapter` — the `crates/test-programs` driver guest calls adapters through `emery_sdk::Source`.
- Adapters depend on `emery-sdk` (the adapter SDK's new name) alone — `[dependencies]` is that one crate: `emery_sdk::source_adapter!` in the guest module, `use emery_sdk::{Context, Seam, Evidence, Error, Model, …}` everywhere. There is no `emery-source` crate.
- The graded live eval is a public-contract client of the shipped `emery` binary, recreated as the root example `examples/eval` (`cargo run --example eval -- [case..]`) — operator-invoked, never CI. Each case under `examples/eval/cases/<name>/expected.toml` names a fixture tree, the stems every accepted requirement must lead with, and the requirements and criteria a reviewer would write from the code, each a `stem`, an `anchor` (`path#Ln[-Lm]`), and a `gloss`; the runner stages each case as its own project beneath `target/eval/`, runs `emery specify` over it `EVAL_RUNS` times (three) with the SDK at trace so the `accepted` lines carry each seam's evidence, reads the committed documents back through `emery show --format json`, grades each run by anchor overlap and stem, reads the backend's `completion` lines for tokens and wall time, and writes a dated scorecard beside them. Four cases: `orders` (one module under one stem), `express-orders` (an Express service, `examples/typescript/express-orders/`: `start`, `orders`, `customers`, `health`), `cli-jobs` (a commander CLI with a node-cron job and a bullmq worker, `examples/typescript/cli-jobs/`: `start`, `import`, `reconcile`, `nightly`, `serve`, `invoices`), and `r9k` (the Kafka consumer, gitignored). `EMERY_BIN` and `TYPESCRIPT_WASM` name the binaries (a sibling `../emery` release build and the release component by default); `make eval` is not restored.
- Measured under the eval (`composer-2.5`, two runs a case) against the survey by model it replaces: the stems are exact on every run of every case where the model's survey had missed or invented one on every run (`live` / `ready` for `health`, `invoice-worker` for `invoices`, `on-message` for `kafka-consumer`, `orders` or three verbs for `order-service`), and every matched requirement of a per-stem seam lands under its stem, where a third to a half had not; requirement recall holds or rises on `cli-jobs` (17/17 both runs, criteria 9/9), `express-orders` (30/30 and 27/30, criteria 10/11 and 9/11), and `orders` (6/6), and falls on `r9k` (28/32 both runs, criteria 7/10 and 8/10, from 30–32/32 and 5–7/10): the model, no longer asked to copy types, reads the helper modules more lightly and claims a Key Vault fetch or a block-management lookup as a `call` rather than the `requirement` beside it, which the prompt now says twice — a module a surface reaches is read for its own rules, and a `call` with no requirement beside it is a behaviour left unstated. `express-orders` opens eight completions in 142–156 s over 370–570 K input tokens where it had opened nine or ten in 168–238 s over 560–760 K; run-to-run id stability rises on `cli-jobs` (29% from 13%) and is unchanged elsewhere. The design's domain model grows to every declaration — 32 blocks on `express-orders` from 9–13, 16 on `r9k` from 6 — of which 27, 13, and 7 of 8 are exported; the one wart is a local alias declared in two route modules, keyed apart by anchor. Decided from the card: no per-seam `verify` hook (no criterion cited an anchor off the Boundaries list and no `callee` was misspelled — the misses are omissions, which a check cannot supply); no mechanical `call` claims (the observed failure is a `call` standing in for a requirement, which more calls would reinforce); no survey fallback by model (nothing to fall back from); a tools-less completion path stays omnia-cursor's to weigh — no evidence turn the card records read a reference document (the SDK logged no `responded` for `list_docs` or `read_doc`; what the backend's own tool calls were, the card does not identify), so the reference tools cost their schema and nothing more. Two of eighteen runs failed past extraction, in the engine's `spec-draft` over ninety-odd requirements (a schema disagreement the backend could not repair; a budget exhausted), which the card records as the run's exit; both followed a larger drafted volume, so an adapter change that raises the count of requirements reaches them. Revisited after that card — the copied declarations are cut to the exported ones, the surface lines carry their ids and what they reach, the brief lists the calls the code makes through packages, and the eval runs each case three times (`EVAL_RUNS` defaults to `3`; the `express-orders` expected set rests the order-caching criterion on `ORDER_CACHE_TTL_SECONDS` at `src/services/orders.ts#L13` rather than the `CACHE_TTL_SECONDS` default it overrides, and the `r9k` set drops the two bare `setTimeout` literals the criterion rule excludes) — and measured again below.
- The component rung is rebuilt on omnia's `test-programs` pattern. `crates/test-programs` replaces `examples/caller` and `examples/conformance`: its `build.rs` runs one `omnia_test::build::Components` build into one `gen.rs` — every `sources/*` component as `ADAPTER_<NAME>` + `foreach_adapter!`, every `programs/<group>/<scenario>.rs` guest program as `<GROUP>_<SCENARIO>` + `foreach_<group>!`. The one driver (`source/extract`: `metadata`, then `extract` in the mode its arguments name — none: both `SourceInput` arms expecting gated evidence; `refused <code>`: expecting that Omnia refusal class; `echoed`: expecting the helpers' `maximal()` evidence field for field; `types <name>..`: expecting the `type` claims an adapter joins from its own reading of the source, named and anchored over a workspace and unanchored over an inline value; `together`: two `extract`s dispatched at once) and the fixture adapters standing in for the one under test (`probe/refusing`, `probe/upstream`, one per WIT `error` arm; `probe/echo`, answering `maximal()` without a model call; `probe/gated`, an inline corpus over `Seam::whole()`) are programs. Host suites are the root package's: `tests/source.rs` (`foreach_adapter!`, every shipped component — `metadata` opens no completion, each `extract`'s system prompt is the embedded `extract.md`), `tests/probe.rs` (`foreach_probe!` — the error arms, the lowering of every record field, and, once over `gated`, the SDK's request shape, reference tools, lend, and spent-budget refusal under the runtime), and `tests/prose.rs` (`foreach_adapter!` — the adapter's `PROSE` held to its `prose/` tree, the prompt under the 800 non-blank-line cap, its `## Worked example` fence gate-valid under the adapter's source kind; absorbs the per-adapter `tests/registry.rs` and its reference-presence checks). The two component suites share one runner (`tests/support/mod.rs`). The root is now the `emery-adapters` package over `crates/*` + `sources/*`, so the shared CI workflow and `make test` run `cargo nextest run --workspace` (the root alone would skip every adapter's suite); the per-adapter `tests/operations.rs` is gone, its subject — what the adapter itself decides — folded into `tests/source.rs` with no prompt-phrase or SDK-brief pins. The guest side — every program and the adapters' `survey` and `guest` modules — lints for `wasm32-wasip2` as the second pass of `make lint`, since native clippy compiles it to nothing. Debug builds optimise the Cranelift JIT so the component suites compile every component in seconds rather than minutes.

- A shipped adapter's tracing follows the `RUST_LOG` its guest environment carries, which the omnia runtime sets from the run's one level — the host's, the engine's, and every adapter's. A bare `emery` run is command mode's `info`, so the SDK's `source_adapter_extract` boundary span reaches the host and the SDK's progress reaches stderr; the engine's `-v` / `-q` flags move the level a step each way (`-v` debug, `-vv` trace; `-q` warn, `-qq` error, `-qqq` off) and override a process `RUST_LOG`, which a bare run keeps (`emery_sdk=debug`, `off`). The adapters' own code changes nothing, and no component built from this tree imports `omnia:otel/baggage`. The component suites mirror the runtime: the support's `deployment()` names no `omnia_test::host::Deployment::level`, so command mode's `info` is every guest's filter there too, and `probe_telemetry` runs the `telemetry` probe with no driver arguments, proving the boundary span and the adapter's own spans export under that default filter.

### Requires

- Engine revision whose shipped runtime declares the `-v` / `-q` flags through `omnia_sdk::api::command::Verbosity` and whose SDK boundary reloads no filter, over an omnia revision that sets every guest's `RUST_LOG` from the run's level (`DeploymentBuilder::level`, `Mode::level`, `omnia_test::host::Deployment::level`; the manifest `[env]` table, the `runtime!` macro's `env:` key, and `Deployment::env` are gone) and carries no `omnia:otel/baggage` interface. A component built while the SDK read its level from baggage imports that interface and does not instantiate under a runtime without it; one built before that opens at `info` at its own boundary under any engine; one from this tree under an earlier engine opens at omnia's `error`, its progress silent unless the process names `RUST_LOG`.
- Engine revision whose `emery-sdk` is the helper shape — `extract`, `workspace`, `metadata`, the `source_adapter!` export macro; no `survey` module; the one `Seam { text, files, stems, anchors }` shape, the SDK holding every `requirement` to a seam's `anchors`, with `serde_json` and `tracing` re-exported — carries the runtime references as `emery_sdk::RUNTIME` answered by `read_doc` and accepted by `emery_sdk::check`, and re-exports the contract's `Source` capability and the embedded prose (`Doc`, the `prose!` list-and-embed macro over the crate's `prose/` tree, the `body` / `find` lookups) beside the extract-only `emery-prose`, and whose `emery_sdk::extract` reuses a slot as any seam answers, dispatches largest first, and puts a seam that failed upstream once more — the fan-out `documentation`'s finer cut and the `Barrier`'s poisoned hold are written against (the git pin in the root `Cargo.toml`, locked to emery `fan-out-3` at `18793b9f`; `main` once that lands). The first adapter train publish waits on an engine release tag.

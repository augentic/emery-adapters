## 0.13.0

Unreleased

### Changed

- Adapters are guests of the `source-adapter` world, written the way every omnia guest is (engine `emery-sdk` 0.38): a `mod guest` at the top of `src/lib.rs`, for `wasm32` alone, invokes `emery_sdk::source_adapter!(metadata, extract)` — one macro in the shape of omnia's `command!(entry)`, which implements the world's `Guest` on a private type and exports it over the two plain fns it names — and writes them: `fn metadata() -> AdapterMetadata` answers `emery_sdk::metadata(SourceKind::..)`, and `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>` is the crate's `survey` for the seams then `emery_sdk::mine(ctx, DOCS, &seams).await`, which runs one gated turn per seam under the embedded `prompts/extract.md` and joins the answers. The `Context` carries the model: the SDK lifts the WIT input and the host's model (`emery_sdk::Provider`, on the WASI defaults) onto it before `extract` is called and lowers the outcome onto the WIT `evidence` and `error` after, so no adapter names a binding or a backend. The rest of `src/lib.rs` is `pub mod survey` and the crate's prose list, `pub static DOCS: &[Doc] = emery_sdk::prose!("../prose", [..]);`; `src/survey.rs` is the one fn with logic of its own, a plain fn over the `SourceInput` when it asks nothing. There is no `SourceAdapter` trait, no `source!` macro, no `src/operations.rs`, and no `export` feature: the guest module is `cfg(target_arch = "wasm32")` in each crate. `EvidenceTurn`, the free `evidence`, `content_note`, `registry::body`, and the SDK's `types` module are gone with the earlier shape; the SDK re-exports the contract's types at its root and omnia's `model` module. The five probes under `crates/test-programs/programs/probe/` are exported the same way; the three that answer without a model return their outcome as a ready future.
- The live examples are the `emery.toml` configs alone: each binds the shipped component a release build writes (`target/wasm32-wasip2/release/<name>.wasm`) rather than a root-package `[[example]]` cdylib of its own, so the root package has no wasm32 dev-dependencies and `examples/<name>/lib.rs` is gone.
- Every adapter states its seams through its `survey` and hands them to `emery_sdk::mine`, so every model call goes through the SDK's fan-out and join. `documentation` lists a tree through `emery_sdk::survey::list` and cuts it itself into one `Seam::Files` per top-level directory of at least two documents, with the root's own documents and every smaller directory as one more — each call lent the root and told the files to mine; `typescript` lists production source alone (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`; never `node_modules`, `vendor`, `target`, `dist`, `build`, `tests`, `__tests__`, dot entries, declaration files, or `*.test.*` / `*.spec.*`) and mines it one exposed surface per `Seam::Note`, each lending the whole root so imports and `tsconfig.json` resolve (the next bullet); `intent`'s one seam moves into `survey`, and it finds its one file through the same `emery_sdk::survey::list`. Every walk goes through `emery_sdk::survey`, which prunes `spec.md`, `design.md`, and `.omnia/` wherever they appear — so a projection beside the brief no longer makes the tree two files. A documentation tree that cuts into fewer than two groups, and an inline value, stay one `Seam::Whole` — a single call, as before. On a tree that does split, claim order changes once: `REQ-nnn` renumbers on the project's next `specify`.
- `documentation`'s and `typescript`'s prompts describe the seam a call is given — the whole tree, or the files the message lists beneath `$SOURCE_DIR` — and steer ids to lead with the domain noun of that seam, so two calls over one tree do not name one requirement twice; `typescript`'s reads beyond the listed modules only to resolve what they reach.
- `typescript` surveys by model, and each seam is one surface the source exposes: on every tree with production source it asks the model once, under its new `prose/prompts/survey.md`, for the boundary — the routes, commands, jobs, and exported APIs a caller outside the source reaches, each with the module the caller enters it at — through `emery_sdk::survey::surfaces`, which lends the root, lists nothing — the model reads the tree, and the turn does not grow with the estate — and holds the answer to the tree under the adapter's `keep` (a surface entered at no file, at a test, a declaration file, a dependency, or build output, a nameless one, or a name listed twice goes back as findings). Each surface becomes one `Seam::Note` that lends the whole root and names the surface and its entry, so the extract call starts there, follows what the surface reaches through imports and `tsconfig.json`, and claims what a caller observes through it; several surfaces may enter at one module, a module no surface enters is mined through the surfaces that reach it, and there is no floor, no fold, and no remainder — the model finds the boundary and never groups what lies behind it. Discovery by surface replaces both the cut by directory, which split every route from its service, and the grouping by surface, which asked the model to walk each surface's modules before any was mined and gated the survey on a tree of several directories, so a service under one `src/` was never surveyed. A tree the model finds no surface in — a tree with no production module among them — is `bad_request` after the one turn: a source no caller reaches is incomplete input or a failed discovery, and mining it whole would raise what no caller observes into requirements. An inline value stays one `Seam::Whole` with no survey turn spent. A survey that asks the model is `async fn survey<P: Model>(model, ctx, docs)` on every target, called from the guest's `extract` as `survey::survey(&Provider, ctx, DOCS).await?`, so tests bind `Scripted` in the slot the guest binds `Provider` and nothing in `src/survey.rs` is `cfg`-gated; `documentation`'s and `intent`'s, which ask nothing, are plain fns over the `Context`, called as `survey::survey(ctx)?`. A second prompt, `prompts/survey.md`, is held by `tests/prose.rs` to the same cap with a worked example that parses as `survey::Inventory`, and `typescript` requires it. The component suite's `typescript` case scripts the survey turn its workspace `extract` opens first — an inventory entering at the fixture's one module — and asserts the compiled-in survey prompt is its system and the surface and entry cross the boundary into the extract turn.
- `sources/<name>/tests/survey.rs` asserts the survey natively: how a tree cuts, what it leaves out, and when it stays whole — as plain tests with no model for `documentation` and `intent`; `typescript`'s scripts an inventory over `omnia_test::guest::Scripted` and a real `tempfile` tree and asserts the entries its `keep` refuses, the notes it cut — one per surface, naming it and its entry — and what it refuses.
- The component suites gain the `fanout` probe and `probe_fanout`: a fixture adapter that mines two `Seam::Note` seams, run over the support's `Barrier` — a `ScriptedModel` that answers a completion only once a party of them is pending and fails it after a bounded hold otherwise. It guards the host property the SDK's fan-out rests on, that the completions one guest issues together are pending together; `support::run` now takes any `Strict` host model rather than `ScriptedModel` alone.
- Adapters name their `emery_sdk::SourceKind` (formerly `Authority`) — the kind of source they read — in their `metadata` answer; "authority" now names only the precedence those kinds rank by.
- The kind of source rides the component's `metadata`, not its Evidence: `emery_sdk::metadata(kind)` reports it beside the `emery-version` pin, the engine reads it once at load and ranks every document the adapter returns by it, and the Evidence a component returns is claims alone (the WIT `evidence` record and the SDK's `Evidence` lose `kind`; a document-level `kind` in a model answer is a schema miss the backend corrects). `emery_sdk::Answer` is gone with it — `tests/prose.rs` parses each worked example as `Evidence` directly — and the driver's `echoed` mode proves the kind the probe declares crosses the bindings through `metadata`.
- Cut to extract-only (ADR-0008 / ADR-0009): each source adapter exports `extract` + `metadata` only. Survey prompts, the target axis (`vectis`, `omnia`, `contracts`), and the extra extract sources (`captures`, `screenshots`) are deleted from the live tree — retrieve them at tag `v1`.
- Adapter code names one engine crate, `emery_sdk::`: the contract types, the embedded prose (`emery_sdk::Doc`, `emery_sdk::prose!`, the `emery_sdk::prose` lookups and `prose::check`), and, for the driver programs, the `Source` capability are all re-exported by the SDK. Until an engine release tag carries that SDK, `[patch.crates-io]` fetches `augentic/emery` by git (path patches stay commented for sibling co-development).
- The embedded prose lives in the engine's `emery-prose` crate and reaches an adapter through the SDK: the crate lists its tree as `pub static DOCS: &[Doc] = emery_sdk::prose!("../prose", ["prompts/extract.md", ..]);` at its root (the `registry!` macro's new name and shape, after `include_str!`: the tree is a path relative to the invoking file, each document is named by its tree-relative path, and the expansion is the table itself, every body an `include_str!`), and the root `tests/prose.rs` holds each list to its tree with `emery_sdk::prose::check` — every document under `prose/` listed once, every relative link a listed document — so the root package names each adapter crate as a native dev-dependency and reads the prompts from the table; an adapter has no `[build-dependencies]` and no `build.rs`. The WIT contract lives in the `emery-adapter` contract crate, named for the `emery:adapter` package, as its `source` axis module; the SDK re-exports it, `Source` included, so nothing in this workspace depends on `emery-adapter` — the `crates/test-programs` driver guest calls adapters through `emery_sdk::Source`.
- Adapters depend on `emery-sdk` (the adapter SDK's new name) alone — `[dependencies]` is that one crate: `emery_sdk::source_adapter!` in the guest module, `use emery_sdk::{Context, Seam, Evidence, Error, Model, …}` everywhere. There is no `emery-source` crate.
- The graded live eval is a public-contract client of the shipped `emery` binary — one `specify` per case over the built components, `emery show spec` for grading, a dated scorecard — operator-invoked, never CI. Its `examples/eval` runner and `make eval` are removed from the tree pending recreation as a root example beside `examples/<name>/`, whose configs it will drive as its cases.
- The component rung is rebuilt on omnia's `test-programs` pattern. `crates/test-programs` replaces `examples/caller` and `examples/conformance`: its `build.rs` runs one `omnia_test::build::Components` build into one `gen.rs` — every `sources/*` component as `ADAPTER_<NAME>` + `foreach_adapter!`, every `programs/<group>/<scenario>.rs` guest program as `<GROUP>_<SCENARIO>` + `foreach_<group>!`. The one driver (`source/extract`: `metadata`, then `extract` in the mode its arguments name — none: both `SourceInput` arms expecting gated evidence; `refused <code>`: expecting that Omnia refusal class; `echoed`: expecting the helpers' `maximal()` evidence field for field) and the fixture adapters standing in for the one under test (`probe/refusing`, `probe/upstream`, one per WIT `error` arm; `probe/echo`, answering `maximal()` without a model call; `probe/gated`, an inline corpus over `Seam::Whole`) are programs. Host suites are the root package's: `tests/source.rs` (`foreach_adapter!`, every shipped component — `metadata` opens no completion, each `extract`'s system prompt is the embedded `prompts/extract.md`), `tests/probe.rs` (`foreach_probe!` — the error arms, the lowering of every record field, and, once over `gated`, the SDK's request shape, reference tools, lend, and spent-budget refusal under the runtime), and `tests/prose.rs` (`foreach_adapter!` — the adapter's `DOCS` held to its `prose/` tree, the prompt under the 800 non-blank-line cap, its `## Worked example` fence gate-valid under the adapter's source kind; absorbs the per-adapter `tests/registry.rs` and its reference-presence checks). The two component suites share one runner (`tests/support/mod.rs`). The root is now the `emery-adapters` package over `crates/*` + `sources/*`, so the shared CI workflow and `make test` run `cargo nextest run --workspace` (the root alone would skip every adapter's suite); the per-adapter `tests/operations.rs` is `tests/survey.rs`, trimmed to what the adapter itself decides — no prompt-phrase or SDK-brief pins. The guest side — every program and the adapters' `guest` modules — lints for `wasm32-wasip2` with the clippy command in `AGENTS.md`, which native clippy compiles to nothing. Debug builds optimise the Cranelift JIT so the component suites compile every component in seconds rather than minutes.

### Requires

- Engine revision whose `emery-sdk` is the helper shape — `mine`, `survey`, `metadata`, the `source_adapter!` export macro — and re-exports the contract's `Source` capability and the embedded prose (`Doc`, the `prose!` list-and-embed macro, the `prose` lookups and `check`) beside the extract-only `emery-prose` (the git pin in the root `Cargo.toml`, currently emery `main`). The first adapter train publish waits on an engine release tag.

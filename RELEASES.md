## 0.13.0

Unreleased

### Changed

- Every adapter states its materials through `SourceAdapter::survey` and none overrides `extract`, so every model call goes through the SDK's fan-out and join. `documentation` cuts a tree into one `Material::Within` per top-level directory of at least two documents — each lent its own directory — with the root's own documents and every smaller directory as one more; `typescript` cuts the same way over production source alone (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`; never `node_modules`, `vendor`, `target`, `dist`, `build`, `tests`, `__tests__`, dot entries, declaration files, or `*.test.*` / `*.spec.*`) into one `Material::Prepared` note per group that lends the whole root and names the modules the call mines, so imports and `tsconfig.json` resolve; `intent`'s one material moves into `survey`. Both walks go through `emery_sdk::survey`, which prunes `spec.md`, `design.md`, and `.omnia/` wherever they appear. A tree that cuts into fewer than two groups, and an inline value, stay one `Material::Bound` — a single call, as before — so the example fixtures and the seam suites are unchanged. On a tree that does split, claim order changes once: `REQ-nnn` renumbers on the project's next `specify`.
- `documentation`'s and `typescript`'s prompts describe the material a call is given — the whole tree, or the files the message lists beneath `$SOURCE_DIR` — and steer ids to lead with the domain noun of that material, so two calls over one tree do not name one requirement twice; `typescript`'s reads beyond the listed modules only to resolve what they reach.
- `typescript` surveys by model: on a tree of several directories it asks the model once, under its new `prose/prompts/survey.md`, to group the production modules by the externally visible surface they serve — a route, a command, a job, an exported API — through `emery_sdk::survey::by_model`, which lists the candidates, lends the root, checks the answer (a module never offered, in two groups, or an empty group goes back as findings), and folds every group under the floor with every module the model left out into one remainder; each group becomes one `Material::Prepared` note as before, so imports and `tsconfig.json` still resolve. Grouping by surface replaces the cut by directory, which split every route from its service; the remainder is the SDK's, so coverage stays total. A tree no directory cut would split, and an inline value, stay one `Material::Bound` with no survey turn spent, so the example fixtures and the seam suites are unchanged. `SourceAdapter::survey` takes the model — `fn survey<P: Model>(model, ctx) -> impl Future<..> + Send` — so `documentation`, `intent`, and the `fanout` probe return `std::future::ready(..)` over their mechanical cut; a second prompt, `prompts/survey.md`, is held by `tests/prose.rs` to the same cap with a worked example that parses as `survey::Partition`, and `typescript` requires it embedded.
- `sources/<name>/tests/extract.rs` asserts the survey natively over a scripted model: how a tree cuts, what it leaves out, and when it stays whole and spends no turn; `typescript`'s scripts a partition and asserts the candidates it offered and the notes it cut.
- The seam suites gain the `fanout` probe and `probe_fanout`: a fixture adapter whose survey is two `Material::Prepared` notes, run over the support's `Barrier` — a `ScriptedModel` that answers a completion only once a party of them is pending and fails it after a bounded hold otherwise. It guards the host property the SDK's fan-out rests on, that the completions one guest issues together are pending together; `support::run` now takes any `Strict` host model rather than `ScriptedModel` alone.
- Adapters declare `const KIND: SourceKind` (`emery_sdk::SourceKind`, formerly `Authority`) — the kind of source they read; "authority" now names only the precedence those kinds rank by.
- The kind of source rides the component's `metadata`, not its Evidence: the SDK's default `metadata` reports `KIND` beside the `emery-version` pin, the engine reads it once at load and ranks every document the adapter returns by it, and the Evidence a component returns is claims alone (the WIT `evidence` record and the SDK's `Evidence` lose `kind`; a document-level `kind` in a model answer is a schema miss the backend corrects). `SourceAdapter::stamp` and `emery_sdk::Answer` are gone with it — `tests/prose.rs` parses each worked example as `Evidence` directly — and the seam's `echoed` mode proves the probe's `KIND` crosses the bindings through `metadata`. Adapter code is unchanged: `const KIND` was already the declaration.
- Cut to extract-only (ADR-0008 / ADR-0009): each source adapter exports `extract` + `metadata` only. Survey prompts, the target axis (`vectis`, `omnia`, `contracts`), and the extra extract sources (`captures`, `screenshots`) are deleted from the live tree — retrieve them at tag `v1`.
- Engine crates import under their package names (`emery_sdk::`, `emery_prose::`, `emery_adapter::`). Until an engine release tag carries the extract-only SDK, `[patch.crates-io]` fetches `augentic/emery` by git (path patches stay commented for sibling co-development).
- The embedded prose registry moved to `emery-prose`: adapters call `emery_prose::registry!()` and name `emery_prose::registry::Doc`, with `emery-prose` declared twice (runtime for the registry, build-time with the `emit` feature for the walker). The WIT contract lives in the `emery-adapter` contract crate, named for the `emery:adapter` package, as its `source` axis module; the SDK re-exports it, and the `crates/test-programs` guest helpers depend on it directly (`emery_adapter::source::{Source, SourceInput, Evidence, …}`).
- Adapters depend on `emery-sdk` (the adapter SDK's new name) alone: `emery_sdk::source!(crate::Adapter)` at the crate root, `use emery_sdk::{SourceAdapter, Context, Material, Evidence, Error, Model, …}` everywhere else. There is no `emery-source` crate.
- The graded live eval is a public-contract client of the shipped `emery` binary — one `specify` per case over the built components, `emery show spec` for grading, a dated scorecard — operator-invoked, never CI. Its `examples/eval` runner and `make eval` are removed from the tree pending recreation as a root example beside `examples/<name>/`, whose configs it will drive as its cases.
- Adapters implement the reshaped `SourceAdapter` (engine `emery-sdk`): `const SOURCE` names the source noun, `extract(model, ctx)` takes the input through `Context { adapter_id, input }`, and the provided `Self::evidence(model, ctx, Material::Bound | Material::Prepared(note))` reads the embedded `prompts/extract.md` itself — `EvidenceTurn`, the free `evidence`, `content_note`, `registry::body`, and the SDK's `types` module are gone; the SDK re-exports the contract's types at its root and omnia's `model` module.
- The component rung is rebuilt on omnia's `test-programs` pattern. `crates/test-programs` replaces `examples/caller` and `examples/conformance`: its `build.rs` runs one `omnia_test::build::Components` build into one `gen.rs` — every `sources/*` component as `ADAPTER_<NAME>` + `foreach_adapter!`, every `programs/<group>/<scenario>.rs` guest program as `<GROUP>_<SCENARIO>` + `foreach_<group>!`. The one seam driver (`source/extract`: `metadata`, then `extract` in the mode its arguments name — none: both `SourceInput` arms expecting gated evidence; `refused <code>`: expecting that Omnia refusal class; `echoed`: expecting the helpers' `maximal()` evidence field for field) and the fixture adapters standing in for the one under test (`probe/refusing`, `probe/upstream`, one per WIT `error` arm; `probe/echo`, answering `maximal()` without a model call; `probe/gated`, an inline corpus over `Material::Bound`) are programs. Host suites are the root package's: `tests/source.rs` (`foreach_adapter!`, every shipped component — `metadata` opens no completion, each `extract`'s system prompt is the embedded `prompts/extract.md`), `tests/probe.rs` (`foreach_probe!` — the error arms, the lowering of every record field, and, once over `gated`, the SDK's request shape, reference tools, lend, and spent-budget refusal under the runtime), and `tests/prose.rs` (`foreach_adapter!` — the prompt embedded and under the 800 non-blank-line cap, its `## Worked example` fence gate-valid under the adapter's source kind; absorbs the per-adapter `tests/registry.rs`, whose reference-presence checks the embed-time walker already makes). The two seam suites share one runner (`tests/support/mod.rs`). The root is now the `emery-adapters` package over `crates/*` + `sources/*`, so the shared CI workflow and `make test` run `cargo nextest run --workspace` (the root alone would skip every adapter's suite); the per-adapter `tests/operations.rs` is `tests/extract.rs`, trimmed to what the adapter itself decides — no prompt-phrase or SDK-brief pins. `make wasm` (inside `make check`, and a CI job of its own) lints the guest side — every program and the adapters' export shims — for `wasm32-wasip2`, which native clippy compiles to nothing. Debug builds optimise the Cranelift JIT so the seam suites compile every component in seconds rather than minutes.

### Requires

- Engine revision that exports the extract-only `emery-adapter` / `emery-prose` / `emery-sdk` crates under those import names (the git pin in the root `Cargo.toml`, currently emery `main`). The first adapter train publish waits on an engine release tag.

# Emery Adapters — Agent Instructions

Emery's first-party **source adapters**. Each `sources/<name>` is one crate shipping as one WebAssembly component that exports the `source-adapter` world of the `emery:adapter` WIT package: `metadata`, and `extract(SourceInput) -> Evidence` — a typed `SourceInput` (a name and a workspace or inline value) in, one Evidence document of typed claims out. The contract, vocabulary, and coding standards are the engine repository's ([`augentic/emery` AGENTS.md](https://github.com/augentic/emery/blob/main/AGENTS.md)); this repository owns extraction behaviour and prose. The v1 tree is archived at git tag `v1`.

<!-- conventions:begin agents/git -->
## Git

Never `git commit`, `git push`, open or close a pull request, or delete a branch — in this repository or in any sibling checkout — unless the maintainer lifts this for the session, explicitly and for named work. Leave every change uncommitted in the working tree; the maintainer reviews and commits. No plan or to-do list carries a commit, push, or PR step, and an instruction to complete every step does not override this.

## Map

| Path | Role |
| --- | --- |
| `sources/<name>/` | One adapter: `Cargo.toml` (`cdylib` + `rlib`, the `rlib` for the root suite's read of `PROSE`; `[dependencies]` is `emery-sdk` and, where the source demands a parser, the pure-Rust crate that reads it (`typescript`: oxc; `python`: ruff's `ruff_python_parser`, `ruff_python_ast`, and `ruff_text_size`; each scoped to `wasm32` and pinned exactly); no dev dependencies, no build dependencies, no `build.rs`); `src/lib.rs` = `pub static PROSE: &[Doc] = emery_sdk::prose![..]` listing every document under `prose/`, then, for `wasm32` alone, `mod survey;` and `mod guest { emery_sdk::source_adapter!(metadata, extract); fn metadata() .. async fn extract(ctx) .. }`; `src/survey.rs` = `pub fn survey` — or, where the model names the surfaces, `pub fn prepare`, reading the input into the SDK's `Tree` — declaring whatever the survey reads its source with as its children under `src/survey/` (`typescript` and `python` alike: `parse.rs` and `parse/walk.rs`, `resolve.rs`, `surface.rs`, as Code style lays them out), and `static DIALECT: Dialect` beside the keep lists in `survey.rs`; `prose/{extract.md, references/}`, and `prose/survey.md` where a survey turn is put. No `tests/` of its own: what it decides is asserted by the root `tests/source.rs` |
| `crates/test-programs/` | omnia's `test-programs` pattern: guest programs (`programs/source/extract.rs` drives the component boundary; `programs/probe/*` are fixture adapters) and the generated table of every built component |
| `tests/` | Root suites over every shipped component: `source.rs` drives each built adapter under the omnia runtime and asserts what it decides — its seams, its refusals — through what the host sees; `probe.rs` drives the fixture adapters for the boundary itself (the runner both share is `support/mod.rs`); `prose.rs` holds each adapter's `PROSE` to its `prose/` tree and checks its prompts, natively |
| `examples/` | The `emery.toml` configs the shipped `emery` binary runs over the release-built components, pointing at eval case fixtures where a live walk needs them ([examples/README.md](examples/README.md)) |
| `evals/` | The graded live eval, a native workspace member and a public-contract client of the shipped `emery` binary: each case under `cases/<name>/` holds `expected.toml` and a `fixture/` tree (the two vendored ones gitignored, fetched at the commit `expected.toml` names); `src/main.rs` (`cargo run -p evals -- [case..]`) stages each case as its own project under `target/eval/<card>/`, runs `emery specify` over it three times — a run the backend refuses before any claim put again once, one that fails in the engine's turns graded on the claims it accepted — grades the accepted claims and the surveyed surfaces against the expected set through `emery show`, and writes the scorecard to `target/eval/<card>.md` with each run's survey facts and evidence beside its log (`run-N.facts.md`, `run-N.evidence-*.json`); `--facts <case..>` writes the facts alone, with no turn spent, which is how an expectation is written; `cards/` keeps the scorecards a decision in its README rests on and states the protocol an arm follows ([evals/README.md](evals/README.md)). Operator-invoked, never CI; its unit tests cover the run tag, the ladder, and the card's reading of a run |

The root `emery-adapters` package is tests only; it names each adapter crate as a native dev-dependency so `tests/prose.rs` can read its `PROSE`. The one engine crate this workspace depends on, `emery-sdk`, is git-pinned in `[patch.crates-io]` beside `emery-prose`, which arrives beneath it and is patched only so both resolve from the same engine revision; the contract crate `emery-adapter` arrives beneath `emery-sdk` too, and neither is named by an adapter. Uncomment the path patches for sibling co-development and never commit them.

## Invariants

- An adapter is a guest of the `source-adapter` world, written the way every omnia guest is: a `mod guest` in `src/lib.rs`, beneath the `mod survey;` declaration and under the same `cfg(target_arch = "wasm32")`, invokes `emery_sdk::source_adapter!(metadata, extract)` — the one macro, in the shape of omnia's `command!(entry)`, which implements the world's `Guest` on a private type and exports it over the two plain fns it names; no adapter names a binding. `fn metadata() -> AdapterMetadata` answers `emery_sdk::metadata(SourceKind::..)` — the kind of source the adapter reads, which the engine ranks the source by before any extract, and no answer carries it. `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>` is the crate's `survey` for the seams, then `emery_sdk::extract(ctx, PROSE, &seams).await`, then only what the survey read from the source itself joined to the answer (`typescript` and `python` append the `type` claims they copied from the exported declarations and drop any the model answered) — so every model call goes through the SDK — one per seam, and for `typescript` and `python` one survey turn per workspace before them — joined into the source's one document, and no claim an adapter adds comes from a turn. The `Context` is the call — the adapter addressed, the input, and the model every turn is put to; the SDK's lift builds it from the WIT input and the host's model (`emery_sdk::Provider`) and lowers the outcome onto the WIT `evidence` and `error`, so no adapter names a backend: the survey is guest code, compiled for `wasm32` alone, and touches the model only through `emery_sdk::survey::seams`. The adapter's survey inspects its source in the way that source demands, and owns the choice of seams where the source alone decides the cut. `emery_sdk::workspace::list(root, keep)` is only physical workspace traversal: it prunes the engine's own files and asks `keep` about each offered `workspace::Entry` (`entry.hidden()`, `entry.name()`, and `entry.extension()` are the adapter's vocabulary for its policy); `documentation` cuts that listing by top-level directory, a directory of more than sixteen files once more by its subdirectories, while `intent` uses it only to validate and read its one-file carrier. `typescript` and `python` read their trees with a parser instead (oxc; ruff's) into the SDK's `survey::code::Tree`: every kept module parsed through `Parsed::read` over the keep's `Listing`, and the tree settled through the adapter's `Recogniser` (`survey/surface.rs`), which answers what its language alone decides — where each import leads (a module, a package, a data file, `Target::Skipped` for a test module the keep set aside, else unresolved) and what the manifest declares (`resolve.rs`); what a test states (`Module::statements`); the bootstrap, the first module the manifest names, or conventional entry, that runs when loaded (for `python`: a console script's target, a `__main__` guard, or an application constructed at module level, `app = create_app()`); whether an argument is a handler (for `python`, a class too — a viewset registered on a router — never one handed to a package's own function or constructor) and the class a registration hands; where blueprints and routers are mounted; which classes declare data alone; and what the code says at an anchor the survey accepted (`derive`, the `at_*` rules). The SDK's `emery_sdk::survey::seams(ctx, PROSE, &tree)` owns the rest and has the model name the surfaces: it lays the facts — the manifest, the bootstrap, every registration handed to a package outside a handler, every `def` or class under a package's registering decorator (lifecycle hooks set aside), what the entry modules export and what a barrel among them re-exports one hop, the packages imported — into one `survey-<source>` turn under `survey.md`, the manifest and the modules that locate a surface laid whole, where the model names each surface at the lines that register or declare it and the stem its ids lead with; holds the answer to the tree — no surface under the bootstrap's `start`, every module the facts locate a surface in reached by a named surface or listed `unreached`, a finding otherwise and one correction round at a time; derives the rest from the accepted anchors through the recogniser's `derive` — the registration, decorator, or export whole where the survey cited a line of it; the stem the code spells there in place of the survey's; what tells the surface from the others under its stem; a class's decorated or public methods, an id apiece; the caller's `start` from the bootstrap; and the import closure and data files each reaches, as the engine's `crates/sdk` row states them — so two runs that accept the same anchors open the same turns; cuts the seams; renders each brief from what its modules spell — the boundaries, the packages and the calls made through them, the decision points (guards, switches, conditionals, throws, catches, timers) a requirement anchors at, and the behaviours the tree's tests state; and copies the `type` claims of the reached modules. A survey never mines and chooses each seam — one `emery_sdk::Seam { text, files, stems, anchors }`, each field narrowing the turn and an empty one leaving it open: `text` leads the turn (a surface, its entry, its stem, the id its requirements lead with, and the modules it reaches — and, for `typescript` and `python`, the boundaries the seam's modules spell as values, the packages they import, and the calls they make through them — with the standing instructions after; its first line labels the seam in the log); `files` are the files to mine beneath the root — laid into the turn whole, every line numbered, when they fit within `emery_sdk::INLINE_BYTES` together, listed otherwise, and held to as the files a `path` may anchor in — and empty mines the whole lend; `stems` are the stems the seam's `requirement` and `criterion` ids must lead with, which the SDK's `check` holds every id to; `anchors` are the spans, in the claim `path` grammar, where the survey found a behaviour can start or its result is decided — every decision point, `return`, function head, call through a package, boundary, and step a function takes into the tree, and each surface's own lines, never a test's or a data file's — which the SDK holds every `requirement`'s `path` to, so one at a line that only wires comes back to re-anchor or drop, and empty holds it to none (a tree with no surface); `Seam::whole()`, `Seam::files(..)`, `Seam::note(..)`, and `Seam::anchors(..)` build the one-field shapes, and every seam of a workspace is lent the root. It refuses unusable input with `bad_request!` — a tree with no production module — and nothing else: a tree the survey names no surface in is mined under the SDK's mechanical cut (one seam under the manifest's or root directory's name within the budget, one per top-level directory past it), told that no surface was found and to read the code as a library is read. An inline value and a tree a mechanical cut leaves no finer than itself are one `Seam::whole()`; a kept tree within `INLINE_BYTES` (the SDK sums the texts the adapter parsed) is one seam over its modules as `files`; a larger tree is one seam per stem, each carrying the surfaces under it and the union of their closures. `typescript` reads the tree's own tests (`*.test.*`, `*.spec.*`, `test/`, `tests/`, `__tests__/`, `.feature` files) and `python` its own (`test_*.py`, `*_test.py`, `tests.py`, modules under `test/`, `tests/`, `testing/`, `__tests__/`, `features/`, `.feature` files; a test's names and docstrings, a feature's scenarios) as stated behaviour, never as modules to mine: each case's or scenario's title is listed at its line under the seam whose files its imports resolve into, appended to that seam's `files` after the sources, and the prompt holds a test to be read and never anchored — a behaviour the laid code confirms is claimed at the code, one it does not hold is not invented. A survey is a plain fn over the input — all it reads — called from `extract` as `let seams = survey::survey(ctx.input)?;`, or, where the source's surfaces are the model's to name, code that reads the input into the SDK's tree (`survey::prepare`) and hands it to the SDK's one entry (`emery_sdk::survey::seams(ctx, PROSE, &tree).await?`), which puts the survey turn and cuts the seams; an inline value is never surveyed by the model. What a survey decides by code alone is asserted with no turn scripted for it; what it derives from the anchors the model names is asserted through a scripted `Inventory`. The crate lists its prose as `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its root — every document of the crate's `prose/` tree, each named from `src/lib.rs` as `include_str!` names a file and tabled by what follows its `prose/` segment (`extract.md`, the path `read_doc` and `check` know it by) — and the guest hands `PROSE` to `extract`. The list is the crate's, not the guest's, because the root `tests/prose.rs` holds it to the tree, and to the prompts the SDK puts to the model (`extract.md`; `survey.md` too where the survey puts a turn), with `emery_sdk::check`, `emery_sdk::RUNTIME` as the imports, while a listed document the tree lacks fails the build at the list. There is no adapter error type: `emery_sdk::Error` is omnia's, and the WIT `error` variant is lowered and lifted inside the contract crate alone.
- Identity is the crate's version and its `emery:<name>@<semver>` package; resolve-time metadata is the component's `metadata` export. There is no manifest file.
- An adapter's dependencies are `emery-sdk` and the pure-Rust parser its source demands — pinned exactly while it is pre-1.0, scoped to `wasm32` so the native `rlib` the root suite reads carries none of it, and confined to the one module that parses (`typescript`'s and `python`'s `survey/parse/walk.rs`) so the rest of the survey reads the SDK's `survey::code` shapes and the adapter's `Module` over them; never a `build.rs`, a C dependency, or a crate that reaches past WASI.
- Adapters never read the revision store or take lifecycle authority. Preserve gaps as `[unknown]`; keep claims platform-neutral.
- `prose/extract.md` is the one extraction pass: at most 800 non-blank lines, with a `## Worked example` JSON fence that parses as the SDK's `Evidence` (claims alone — the kind of source is the adapter's metadata, never the answer's) and passes the claim gate — `tests/prose.rs` enforces both. Where an adapter has the model name its surfaces, `prose/survey.md` is the one survey prompt, under the same cap, with a `## Worked example` JSON fence that parses as the SDK's `Inventory`, every anchor in the `path` grammar and every stem kebab-case — `tests/prose.rs` enforces those the same way. There is no third prompt: what a survey lays into a turn — the facts it read for the survey, the seam's `text` for the extraction — the prompt describes under its inputs, so the model is told how to read what code found, never how to find it. Every document under `prose/references/examples/` other than `README.md` is a worked example: its `## Evidence` JSON fence parses as `Evidence` and passes the gate, enforced the same way. References are written for the model in the adapter's current contract — what to read, which claims to emit — never addressed to a contributor. References are linked, never inlined, and every link names a document in `PROSE` or one of the SDK's runtime references (`claims.md`, `reconciliation.md`, from a prompt at the `prose/` root) — a directory or an unlisted file is unreadable through `read_doc`, and `tests/prose.rs` refuses it — and every document in `PROSE` is reached from a prompt by those links, or `tests/prose.rs` refuses that too: what nothing links is embedded and never read. A rule the SDK's references state is linked, never restated. Contributor guidance never goes in the embedded corpus.
- Do not commit built `.wasm` artifacts.

## Code style

clippy (`make lint`) and nightly rustfmt (`make fmt`) are the style gate; beyond them and the rules below, match the surrounding code.

- Suppress a lint with `#[expect(lint, reason = "…")]` at the smallest scope, never `#[allow]`.
- `<module>.rs` plus `<module>/<child>.rs`; `mod.rs` only under `tests/support/`.
- A fn over a type is that type's method, not a free fn taking it as its first argument, where the type's module declares the fn or the fn is a plain lookup or predicate on the type. A constructor is an associated fn. A policy `const` sits beside the type whose method reads it. Values several fns thread through every call become one struct whose methods they are. A fn stays free when it is pure over primitives and iterators, or when it is one module's rule applied to another module's type.
<!-- conventions:end agents/code-style -->

<!-- conventions:begin agents/comments -->
Comments follow the conventions `std`, `serde`, and `tokio` converge on: docs state the observable contract for the crate's user, never the body's mechanics.

- `///` goes on the public API only — the `pub` types, fns, fields, variants, and re-exports a user of the crate can reach — never on a private or `pub(crate)` item, an `impl` block, or a trait-impl method. A clap field's `///` is its `--help` text. A doc opens with one summary sentence (about fifteen words, full stop), then a blank line, then short sentences and bullet lists. `# Examples` holds compiled doctests, for non-obvious usage only; `# Errors` names each class the caller matches on, linked; `# Panics` the rest. Every item mentioned is an intra-doc link. No mechanics, history, or migration notes. A `//!` says what a module is for, in the same shape.
- A private item takes a `//` only for what a senior developer would not see from its name and signature: a constraint, a why, an invariant. Most carry nothing. No restatements, match-arm labels, or body paraphrases.
- Inside a body, a `//` is a section header: lowercase, no full stop, above a blank-line-separated block, naming what the block achieves, so the headers read together outline the fn. A fn readable at a glance carries none, and a header never narrates the line beneath it. The one in-body explanation is `// HACK: …`, for a trick a senior would not see through.
- A test fn takes `//`, never `///`, and only for rationale its scenario name and assertions do not expose.
- No commented-out code.
- Every sentence earns its place and reads once: short plain sentences, one idea each; three or more things are a bullet list, not a colon-and-dash clause; no chained em-dashes, nested parentheticals, or semicolon runs; each fact has one home across `//!`, `///`, and `//`. A comment is as long as its why takes and no longer — concise is not dense, and readable is not verbose.
<!-- conventions:end agents/comments -->

The guest deny-list in [`clippy.toml`](clippy.toml) is part of the gate beside the shared `[workspace.lints]`. In an adapter the public API is the crate's `//!` and `PROSE`, since `survey` is private.

An adapter crate's `//!` docs state the source it accepts, how that source is divided for extraction, and any refusal visible to a caller — not the `wasm32` module layout, the guest-macro wiring, or how `PROSE` is checked.

A fn over one of the survey's types is that type's method, as the rule above has it. The adapter's recogniser (`typescript::TypeScript`, `python::Python` in `survey/surface.rs`) holds the `Resolver` and the manifest reader, and its `Recogniser` impl is where the language's rules answer the SDK: `bootstrap`, `handler`, `mounts`, and `derive`, with the `at_*` rules a `derive` dispatches to — a method where one reads the recogniser, a free fn over the SDK's `Tree` otherwise. `Module::parse` constructs; `Module::declared_at` and `Decorated::registering` look up and decide; the SDK's `Tree` (`closure`, `reaches`, `receiver`, `registration_at`, `identify`) carries what the rules would otherwise thread through every call. The module data model is the SDK's (`emery_sdk::survey::code`: `Module` and its lookups, `Import`, `Export`, `Binding`, `Call`, `Decorated`, `ClassDecl`, `TypeDecl`, and the rest), and an adapter's `parse.rs` wraps its `Module` — `Deref` to the core, `Module::parse`, `settle_exports`, and `statements` as methods, the fields its language alone fills beside it (`python`'s `main_guard`, `tests`, `all`) — with `parse/walk.rs` the one producer; a rule of the adapter's over an SDK type (`python`'s `declares_data`) is a free fn in `parse.rs`. What a lookup reads of the language is data, not code: the adapter's one `static DIALECT: emery_sdk::survey::Dialect` in `survey.rs`, passed to each lookup that reads one, with `DIALECT.route` the `Spelling` the route rules take; a policy list `Dialect` does not carry — the bootstraps, the verbs, the mounting methods, the data bases — sits beside the fn that reads it. A rule `surface` applies to a `Module` (`export_at`, `decorated_at`) stays its free fn, as does `unique`, pure over lists. What is pure over strings and reads no `Module` is the SDK's (`kebab`, `survey::Lines`, `survey::resolve`, `survey::route`, `survey::tests`), never an adapter's copy, and so is what the SDK reads of the language for the facts and the briefs: a `Dialect` field, never a `const` of the adapter's.

## Testing

Tests drive the public boundary: a behaviour is asserted through what a user of the product or crate can reach, over scripted doubles rather than a live filesystem, network, or model, never through private internals. A suite below the root survives only for an independent library contract; a unit test only for a branch no public boundary reaches. A test fn names the scenario (`gen_spec`, `no_sources`), never the outcome. Scripted doubles are strict: script exactly the exchanges a run consumes.
<!-- conventions:end agents/testing -->

- An adapter's one contract is the `source-adapter` world, so what it decides is asserted through it: the root `tests/source.rs` runs the built component under the omnia runtime over a scripted host model and reads what the host sees. A workspace `extract` opens one completion per seam the survey chose — the strict script consumes exactly that many — each under the embedded `extract.md` and carrying the seam's data: the files a seam lists, the brief `intent` read through the mount, the surface lines, boundaries, and packages the SDK lays for `typescript` and `python` from what their recognisers derived (what the tree decided, never the SDK's standing prompt text). Where the survey puts a turn, that turn opens first, under the embedded `survey.md` with the workspace lent and the survey schema, and the script answers it with an `Inventory` — the `inventory(..)` helper's surfaces and `unreached` — before the seam answers, one `Seen` per correction round where a finding sends the answer back, its `check` exchange recorded as the round's outcome; the scenario asserts what code derived from the anchors it scripted (the stems, ids, methods, closures, and notes the seams' briefs carry) and the facts the survey turn laid, never the answer's own words back; a refusal runs the driver's `refused <code> [<value>]` mode, lifting to its omnia class with no turn spent past it; what an adapter joins to the answer beyond the model's claims — `typescript`'s and `python`'s parsed `type` claims — runs the driver's `types <name>..` mode, which asserts the names and `#L` anchors the host sees over a workspace, then the unanchored ones over an inline value. An adapter has no tests of its own and no dev dependencies. Never pin prompt phrases; prompt quality is the live eval's.
- Root `tests/`: every shipped component, the boundary, and the corpus. `foreach_adapter!` and `foreach_probe!` make a new adapter or probe a compile error until `source.rs`, `prose.rs`, or `probe.rs` names it; that test carries its adapter's or program's name (`intent`, `probe_echo`), and an adapter's further scenarios are `<name>_<scenario>` (`documentation_directories`, `intent_empty_brief`). `prose.rs` runs `emery_sdk::check(<name>::PROSE, ..)` over the adapter's tree and the prompts it names, then the prompt checks, so a new adapter is also a root dev-dependency, and a guest package `wasm-packages` in [`conventions.toml`](conventions.toml) names.
- What the SDK does for every adapter (the request shape, the reference tools, the lend, the claim gate's repair and spent-rounds refusal, the check of every anchor and id against its seam) is asserted once in the SDK's own suite and once under the runtime over the `gated` probe — never per adapter; an adapter's tracing follows its guest environment's `RUST_LOG`, which the runtime sets from the run's one level — command mode's `info` under the support's `deployment()`, which names no `Deployment::level`, as under a bare run of the shipped `emery` runtime — and that the SDK's `source_adapter_extract` boundary span exports under command mode's default filter alongside the adapter's own spans is asserted once, over the `telemetry` probe. The host property the SDK's fan-out rests on — the completions one guest issues together are pending together — is guarded once, over the `fanout` probe behind the support's `Barrier` model; the one the engine's fan-out over sources rests on — the link dispatches one caller issues together run together — once more, over the same probe in the driver's `together` mode.
- Always `cargo nextest`, and `--workspace` from the root as `make test` and CI do; every suite is the root package's today, so `cargo nextest run -p emery-adapters` runs the same tests.
- The guest side (`crates/test-programs/programs/`, the adapters' `survey` and `guest` modules) is `cfg(target_arch = "wasm32")`, which native clippy compiles to nothing, so `make lint` runs the shared `lint-wasm` pass — clippy over every lib, bin and example (never tests or benches) of the guest packages for `wasm32-wasip2`, the adapters and `test-programs` as `wasm-packages` in `conventions.toml` names them, since the root package and the `evals` harness are native — over it (the command below); `make conventions-sync` renders that list into `.github/workflows/ci.yaml`, `WASM32_PACKAGES` in `mise.toml` mirrors it by hand, and `make conventions-check` holds the two together; `make test` compiles the guest side through the component build alone.

## Commands

All from the repository root through `make` ([`Makefile`](Makefile) → mise). The tasks are the shared `mise/rust.toml` of [`augentic/toolkit`](https://github.com/augentic/toolkit), pinned in [`mise.toml`](mise.toml) to the tag every `uses:` under `.github/workflows/` names; a bump is one pull request over both, and `make conventions-check` holds them together.

```bash
make ci # exactly the CI jobs: fmt-check + lint + test + test-docs + docs + vet + deny + conventions-check — run before handing over
make check # local advisories: audit + fmt (rewrites) + lint + outdated + deps
make test # cargo nextest run --locked --workspace --all-features, under -Dwarnings
make lint # lint-host (cargo clippy --workspace --all-targets --all-features, then cargo hack --each-feature), then lint-wasm (the same over every lib, bin and example for wasm32-wasip2 — never tests)
make fmt # cargo +nightly fmt --all
make vet-regen # regenerate cargo-vet imports/exemptions/unpublished, then vet
make conventions-sync # write the shared conventions at the pinned toolkit tag
make cov # cargo llvm-cov nextest --workspace --all-features --summary-only
make sweep # drop target/ artifacts untouched for a week
```

A file with a `Managed by augentic/toolkit` header, and everything between a `conventions:begin` and `conventions:end` marker pair, is written by `make conventions-sync`: never edit it here. Change it in [`augentic/toolkit`](https://github.com/augentic/toolkit) instead. If `make ci` cannot run, say exactly why and which checks ran instead.
<!-- conventions:end agents/commands -->

`publish` is the one local task (it shadows the shared crates.io dry run: this train ships to GHCR).

```bash
cargo nextest run -p emery-adapters --test source # the shipped components alone
cargo run -p evals -- [case..] # the graded live eval over the shipped emery binary; operator-invoked, never CI
cargo clippy -p documentation -p intent -p typescript -p python -p test-programs --lib --bins --examples --all-features --target wasm32-wasip2 -- -D warnings # the guest side alone; the first command of lint-wasm
cargo build -p <name> --target wasm32-wasip2 --release # one component
cargo build --workspace --target wasm32-wasip2 --release # every component
make publish <name> # push one built component to its GHCR tag
```

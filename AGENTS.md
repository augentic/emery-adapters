# Emery Adapters — Agent Instructions

Emery's first-party **source adapters**. Each `sources/<name>` is one crate shipping as one WebAssembly component that exports the `source-adapter` world of the `emery:adapter` WIT package: `metadata`, and `extract(SourceInput) -> Evidence` — a typed `SourceInput` (a name and a workspace or inline value) in, one Evidence document of typed claims out. The contract, vocabulary, and coding standards are the engine repository's ([`augentic/emery` AGENTS.md](https://github.com/augentic/emery/blob/main/AGENTS.md)); this repository owns extraction behaviour and prose. The v1 tree is archived at git tag `v1`.

## Git

Never `git commit`, `git push`, open or close a pull request, or delete a branch — in this repository or in any sibling checkout (`../emery`, `../omnia`, `../omnia-backends`). Leave every change uncommitted in the working tree; the maintainer reviews and commits. No plan or to-do list carries a commit, push, or PR step, and an instruction to complete every step does not override this.

## Map

| Path                        | Role                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sources/<name>/`           | One adapter: `Cargo.toml` (`cdylib` + `rlib`, the `rlib` for the root suite's read of `PROSE`; `[dependencies]` is `emery-sdk` and, where the source demands a parser, the pure-Rust crate that reads it (`typescript`: oxc, scoped to `wasm32` and pinned exactly); no dev dependencies, no build dependencies, no `build.rs`); `src/lib.rs` = `pub static PROSE: &[Doc] = emery_sdk::prose![..]` listing every document under `prose/`, then, for `wasm32` alone, `mod survey;` and `mod guest { emery_sdk::source_adapter!(metadata, extract); fn metadata() .. async fn extract(ctx) .. }`; `src/survey.rs` = `pub fn survey`, beside whatever the survey reads its source with (`typescript`: `parse.rs`, `resolve.rs`, `surface.rs`, `skeleton.rs`); `prose/{extract.md, references/}`. | `crates/test-programs/`     | omnia's `test-programs` pattern: guest programs (`programs/source/extract.rs` drives the component boundary; `programs/probe/*` are fixture adapters) and the generated table of every built component                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `tests/`                    | Root suites over every shipped component: `source.rs` drives each built adapter under the omnia runtime and asserts what it decides — its seams, its refusals — through what the host sees; `probe.rs` drives the fixture adapters for the boundary itself (the runner both share is `support/mod.rs`); `prose.rs` holds each adapter's `PROSE` to its `prose/` tree and checks its prompts, natively                                                                                                                                                                                                                                         |
| `examples/`                 | The `emery.toml` configs the shipped `emery` binary runs over the release-built components, and the fixtures they lend ([examples/README.md](examples/README.md))                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

The root `emery-adapters` package is tests only; it names each adapter crate as a native dev-dependency so `tests/prose.rs` can read its `PROSE`. The one engine crate this workspace depends on, `emery-sdk`, is git-pinned in `[patch.crates-io]` beside `emery-prose`, which arrives beneath it and is patched only so both resolve from the same engine revision; the contract crate `emery-adapter` arrives beneath `emery-sdk` too, and neither is named by an adapter. Uncomment the path patches for sibling co-development and never commit them.

## Invariants

- An adapter is a guest of the `source-adapter` world, written the way every omnia guest is: a `mod guest` in `src/lib.rs`, beneath the `mod survey;` declaration and under the same `cfg(target_arch = "wasm32")`, invokes `emery_sdk::source_adapter!(metadata, extract)` — the one macro, in the shape of omnia's `command!(entry)`, which implements the world's `Guest` on a private type and exports it over the two plain fns it names; no adapter names a binding. `fn metadata() -> AdapterMetadata` answers `emery_sdk::metadata(SourceKind::..)` — the kind of source the adapter reads, which the engine ranks the source by before any extract, and no answer carries it. `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>` is the crate's `survey` for the seams, then `emery_sdk::extract(ctx, PROSE, &seams).await`, then only what the survey read from the source itself joined to the answer (`typescript` appends the `type` claims it copied from the exported declarations and drops any the model answered) — so every model call goes through the SDK, one per seam, joined into the source's one document, and no claim an adapter adds comes from a turn. The `Context` is the call — the adapter addressed, the input, and the model every turn is put to; the SDK's lift builds it from the WIT input and the host's model (`emery_sdk::Provider`, on the WASI defaults — the unit struct with the empty `impl Model` every omnia guest would otherwise declare) before the call, and lowers the outcome onto the WIT `evidence` and `error` after, so no adapter names a backend and nothing inside `src/survey.rs` names a target: the survey is guest code, compiled for `wasm32` alone as the guest is, and never touches the model. The adapter's survey owns the choice of seams and inspects its source in the way that source demands. `emery_sdk::workspace::list(root, keep)` is only physical workspace traversal: it prunes the engine's own files and asks `keep` about each offered `workspace::Entry` (`entry.hidden()`, `entry.name()`, and `entry.extension()` are the adapter's vocabulary for its policy); `documentation` cuts that listing by top-level directory, a directory of more than sixteen files once more by its subdirectories, while `intent` uses it only to validate and read its one-file carrier. `typescript` reads its tree with a parser instead: every kept module parsed, the surfaces derived from what the code does — the module the manifest boots when it runs, the callbacks registered on package-derived receivers, the methods under package decorators, the exports of a library with no bootstrap — each with its entry, its stem, and the import closure it reaches (the bootstrap's stopping at every other surface's entry and reaching what each stopped entry constructs — its class fields' types, its module-level bindings' initializers), so two runs over one tree open the same turns; each seam's text lays what its modules spell — the boundaries, the packages and the calls made through them, the decision points (guards, switches, conditionals, throws, catches, timers) a requirement anchors at, and the behaviours the tree's tests state. The helper defines no shape of adapter survey. A survey never mines and chooses each seam — one `emery_sdk::Seam { text, files, stems, anchors }`, each field narrowing the turn and an empty one leaving it open: `text` leads the turn (a surface, its entry, its stem, the id its requirements lead with, and the modules it reaches — and, for `typescript`, the boundaries the seam's modules spell as values, the packages they import, and the calls they make through them — with the standing instructions after; its first line labels the seam in the log); `files` are the files to mine beneath the root — laid into the turn whole, every line numbered, when they fit within `emery_sdk::INLINE_BYTES` together, listed otherwise, and held to as the files a `path` may anchor in — and empty mines the whole lend; `stems` are the stems the seam's `requirement` and `criterion` ids must lead with, which the SDK's `check` holds every id to; `anchors` are the spans, in the claim `path` grammar, where the survey found a behaviour can start or its result is decided — for `typescript`, every decision point, every `return` of a value, every call through a package, every boundary, and each surface's own lines, never a test's — which the SDK holds every `requirement`'s `path` to, so one at a line that only wires comes back to re-anchor or drop, and empty holds it to none (a tree with no surface); `Seam::whole()`, `Seam::files(..)`, and `Seam::note(..)` build the one-field shapes, and every seam of a workspace is lent the root. It refuses unusable input with `bad_request!` — a tree with no production module — and nothing else: a tree the parser finds no surface in is mined under a mechanical cut (within the budget, one seam over every module under the manifest's or the root directory's name as its stem; past it, one seam per top-level directory, the root's own modules joined to the first), told that no surface was found and to read the code as a library is read. An inline value and a tree a mechanical cut leaves no finer than itself are one `Seam::whole()`; a kept tree within `INLINE_BYTES` (`emery_sdk::workspace::size`) is one seam over its modules as `files`; a larger tree is one seam per stem, each carrying the surfaces under it and the union of their closures. `typescript` reads the tree's own tests (`*.test.*`, `*.spec.*`, `test/`, `tests/`, `__tests__/`, `.feature` files) as stated behaviour, never as modules to mine: each case's or scenario's title is listed at its line under the seam whose files its imports resolve into, appended to that seam's `files` after the sources, and the prompt holds a test to be read and never anchored — a behaviour the laid code confirms is claimed at the code, one it does not hold is not invented. A survey is a plain fn over the input — all it reads — called from `extract` as `let seams = survey::survey(ctx.input)?;`; no survey asks the model, so what one decides is asserted with no turn scripted for it. The crate lists its prose as `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its root — every document of the crate's `prose/` tree, each named from `src/lib.rs` the way `include_str!` names a file and embedded as it embeds one, and tabled by what follows its `prose/` segment (`extract.md`, the path `read_doc` and `check` know it by) — and the guest hands `PROSE` to `extract`. The references every adapter shares — the claim `id` grammar, `path` anchors, the skip roots, the fail-closed gate, and the `specify` pipeline — are the SDK's, not this repository's: `emery_sdk::RUNTIME` embeds them as `claims.md` and `reconciliation.md`, `read_doc` answers them after the adapter's own table, and a prompt at its `prose/` root links them as `claims.md` without any adapter listing them. The list is the crate's, not the guest's, because the root `tests/prose.rs` holds it to the tree, and to the prompts the SDK puts to the model, with `emery_sdk::check`, `emery_sdk::RUNTIME` as the imports: a document under `prose/` the list leaves out, a path listed twice, a relative link neither a listed document nor a runtime reference answers, a listed document no prompt reaches through those links, or a listed document at a runtime reference's path fails that suite, while a listed document the tree lacks fails the build at the list. There is no adapter error type: `emery_sdk::Error` is omnia's, and the WIT `error` variant is lowered and lifted inside the contract crate alone.
- Identity is the crate's version and its `emery:<name>@<semver>` package; resolve-time metadata is the component's `metadata` export. There is no manifest file.
- An adapter's dependencies are `emery-sdk` and the pure-Rust parser its source demands — pinned exactly while it is pre-1.0, scoped to `wasm32` so the native `rlib` the root suite reads carries none of it, and confined to the one module that parses (`typescript`'s `parse.rs`) so the rest of the survey reads the adapter's own types; never a `build.rs`, a C dependency, or a crate that reaches past WASI.
- Adapters never read the revision store or take lifecycle authority. Preserve gaps as `[unknown]`; keep claims platform-neutral.
- `prose/extract.md` is the one extraction pass: at most 800 non-blank lines, with a `## Worked example` JSON fence that parses as the SDK's `Evidence` (claims alone — the kind of source is the adapter's metadata, never the answer's) and passes the claim gate — `tests/prose.rs` enforces both. It is the one prompt: what a survey lays into a seam's `text` the prompt describes under its inputs, so the model is told how to read what code found, never how to find it. Every document under `prose/references/examples/` other than `README.md` is a worked example: its `## Evidence` JSON fence parses as `Evidence` and passes the gate, enforced the same way. References are written for the model in the adapter's current contract — what to read, which claims to emit — never addressed to a contributor. References are linked, never inlined, and every link names a document in `PROSE` or one of the SDK's runtime references (`claims.md`, `reconciliation.md`, from a prompt at the `prose/` root) — a directory or an unlisted file is unreadable through `read_doc`, and `tests/prose.rs` refuses it — and every document in `PROSE` is reached from a prompt by those links, or `tests/prose.rs` refuses that too: what nothing links is embedded and never read. A rule the SDK's references state is linked, never restated. Contributor guidance never goes in the embedded corpus.
- Do not commit built `.wasm` artifacts.

## Code style

The engine repository's ([`augentic/emery` AGENTS.md § Code style](https://github.com/augentic/emery/blob/main/AGENTS.md)): clippy under the shared `[workspace.lints]` in `Cargo.toml` and the guest deny-list in `clippy.toml`, plus nightly rustfmt (`make fmt`), are the gate; beyond them, match the surrounding code. `#[expect(lint, reason = "…")]` at the smallest scope, never `#[allow]`. Rustdoc (`///`) on `pub` items only; no history in comments.

An adapter crate's `//!` docs state the source it accepts, how that source is divided for extraction, and any refusal visible to a caller — not the `wasm32` module layout, the guest-macro wiring, or how `PROSE` is checked.

## Testing

- An adapter's one contract is the `source-adapter` world, so what it decides is asserted through it: the root `tests/source.rs` runs the built component under the omnia runtime over a scripted host model and reads what the host sees. A workspace `extract` opens one completion per seam the survey chose — the strict script consumes exactly that many — each under the embedded `extract.md` and carrying the seam's data: the files a seam lists, the brief `intent` read through the mount, the surface lines, boundaries, and packages `typescript` lays (the adapter's own lines, never the SDK's brief text); a refusal runs the driver's `refused <code> [<value>]` mode, lifting to its omnia class with no turn spent past it; what an adapter joins to the answer beyond the model's claims — `typescript`'s parsed `type` claims — runs the driver's `types <name>..` mode, which asserts the names and `#L` anchors the host sees over a workspace, then the unanchored ones over an inline value. An adapter has no tests of its own and no dev dependencies. Never pin prompt phrases; prompt quality is the live eval's.
- Root `tests/`: every shipped component, the boundary, and the corpus. `foreach_adapter!` and `foreach_probe!` make a new adapter or probe a compile error until `source.rs`, `prose.rs`, or `probe.rs` names it; that test carries its adapter's or program's name (`intent`, `probe_echo`), and an adapter's further scenarios are `<name>_<scenario>` (`documentation_directories`, `intent_empty_brief`). `prose.rs` runs `emery_sdk::check(<name>::PROSE, ..)` over the adapter's tree and the prompts it names, then the prompt checks, so a new adapter is also a root dev-dependency.
- What the SDK does for every adapter (the request shape, the reference tools, the lend, the claim gate's repair and spent-rounds refusal, the check of every anchor and id against its seam) is asserted once in the SDK's own suite and once under the runtime over the `gated` probe — never per adapter; an adapter's tracing follows its guest environment's `RUST_LOG`, which the runtime sets from the run's one level — command mode's `info` under the support's `deployment()`, which names no `Deployment::level`, as under a bare run of the shipped `emery` runtime — and that the SDK's `source_adapter_extract` boundary span exports under command mode's default filter alongside the adapter's own spans is asserted once, over the `telemetry` probe. The host property the SDK's fan-out rests on — the completions one guest issues together are pending together — is guarded once, over the `fanout` probe behind the support's `Barrier` model; the one the engine's fan-out over sources rests on — the link dispatches one caller issues together run together — once more, over the same probe in the driver's `together` mode.
- Always `cargo nextest`, and `--workspace` from the root as `make test` and CI do; every suite is the root package's today, so `cargo nextest run -p emery-adapters` runs the same tests.
- The guest side (`crates/test-programs/programs/`, the adapters' `survey` and `guest` modules) is `cfg(target_arch = "wasm32")`, which native clippy compiles to nothing, so `make lint` runs the shared `lint-wasm` pass — clippy over every workspace lib, bin and example (never tests or benches) for `wasm32-wasip2` — over it (the command below); `make test` compiles it through the component build alone.

Toolchain and publishing: [CONTRIBUTING.md](CONTRIBUTING.md).

## Commands

All from the repository root through `make` ([`Makefile`](Makefile) → mise):

The tasks are the shared [`augentic/.github`](https://github.com/augentic/.github) `mise/rust.toml`, pinned in [`mise.toml`](mise.toml) to the same tag the workflows under `.github/workflows/` use; bump both together. `publish` is the one local task (it shadows the shared crates.io dry run: this train ships to GHCR).

```bash
make ci                              # exactly the CI jobs: fmt-check + lint + test + test-docs + docs + vet + deny — run before committing
make check                           # local advisories: audit + fmt (rewrites) + lint + outdated + deps
make test                            # cargo nextest run --locked --workspace --all-features
cargo nextest run -p emery-adapters --test source   # the shipped components alone
make lint                            # lint-host (cargo clippy --workspace --all-targets --all-features, then cargo hack --each-feature), then lint-wasm (the same over every lib, bin and example for wasm32-wasip2 — never tests)
cargo clippy --workspace --lib --bins --examples --all-features --target wasm32-wasip2 -- -D warnings   # the guest side alone; the first command of lint-wasm
cargo build -p <name> --target wasm32-wasip2 --release   # one component
cargo build --workspace --target wasm32-wasip2 --release   # every component
make publish <name>                  # push one built component to its GHCR tag
make vet-regen                       # regenerate cargo-vet imports/exemptions/unpublished, then vet
make sweep                           # drop target/ artifacts untouched for a week
```

If `make ci` cannot run, say exactly which narrower checks ran and why.

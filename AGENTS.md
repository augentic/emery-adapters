# Emery Adapters — Agent Instructions

Emery's first-party **source adapters**. Each `sources/<name>` is one crate shipping as one WebAssembly component that exports the `source-adapter` world of the `emery:adapter` WIT package: `metadata`, and `extract(SourceInput) -> Evidence` — a typed `SourceInput` (a name and a workspace or inline value) in, one Evidence document of typed claims out. The contract, vocabulary, and coding standards are the engine repository's ([`augentic/emery` AGENTS.md](https://github.com/augentic/emery/blob/main/AGENTS.md)); this repository owns extraction behaviour and prose. The v1 tree is archived at git tag `v1`.

## Git

Never `git commit`, `git push`, open or close a pull request, or delete a branch — in this repository or in any sibling checkout (`../emery`, `../omnia`, `../omnia-backends`). Leave every change uncommitted in the working tree; the maintainer reviews and commits. No plan or to-do list carries a commit, push, or PR step, and an instruction to complete every step does not override this.

The root `emery-adapters` package is tests only; it names each adapter crate as a native dev-dependency so `tests/prose.rs` can read its `PROSE`. The one engine crate this workspace depends on, `emery-sdk`, is git-pinned in `[patch.crates-io]` beside `emery-prose`, which arrives beneath it and is patched only so both resolve from the same engine revision; the contract crate `emery-adapter` arrives beneath `emery-sdk` too, and neither is named by an adapter. Uncomment the path patches for sibling co-development and never commit them.

## Invariants

- An adapter is a guest of the `source-adapter` world, written the way every omnia guest is: a `mod guest` in `src/lib.rs`, beneath the `mod survey;` declaration and under the same `cfg(target_arch = "wasm32")`, invokes `emery_sdk::source_adapter!(metadata, extract)` — the one macro, in the shape of omnia's `command!(entry)`, which implements the world's `Guest` on a private type and exports it over the two plain fns it names; no adapter names a binding. `fn metadata() -> AdapterMetadata` answers `emery_sdk::metadata(SourceKind::..)` — the kind of source the adapter reads, which the engine ranks the source by before any extract, and no answer carries it. `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>` is the crate's `survey` for the seams, then `emery_sdk::extract(ctx, PROSE, &seams).await`, then only what the survey read from the source itself joined to the answer (`typescript` and `python` append the `type` claims they copied from the exported declarations and drop any the model answered) — so every model call goes through the SDK — one per seam, and for `typescript` and `python` one survey turn per workspace before them — joined into the source's one document, and no claim an adapter adds comes from a turn. The `Context` is the call — the adapter addressed, the input, and the model every turn is put to; the SDK's lift builds it from the WIT input and the host's model (`emery_sdk::Provider`, on the WASI defaults — the unit struct with the empty `impl Model` every omnia guest would otherwise declare) before the call, and lowers the outcome onto the WIT `evidence` and `error` after, so no adapter names a backend and nothing inside `src/survey.rs` names a target: the survey is guest code, compiled for `wasm32` alone as the guest is, and touches the model only through `emery_sdk::survey::surfaces`. The adapter's survey owns the choice of seams and inspects its source in the way that source demands. `emery_sdk::workspace::list(root, keep)` is only physical workspace traversal: it prunes the engine's own files and asks `keep` about each offered `workspace::Entry` (`entry.hidden()`, `entry.name()`, and `entry.extension()` are the adapter's vocabulary for its policy); `documentation` cuts that listing by top-level directory, a directory of more than sixteen files once more by its subdirectories, while `intent` uses it only to validate and read its one-file carrier. `typescript` and `python` read their trees with a parser instead (oxc; ruff's), and have the model name the surfaces: every kept module parsed, and the facts the parser reads — the manifest, the first module it names, or conventional entry, that runs when loaded (for `python`: a console script's target, a `__main__` guard, or an application constructed at module level, `app = create_app()`), every call outside a handler that hands a function to something a package provides (for `python`, a class too — a viewset registered on a router — never one handed to a package's own function or constructor), every method under a package's decorator (for `python`, every decorated `def` and class, the hooks that shape or attach to a lifecycle set aside), what the entry modules export and what a barrel — a package `__init__` — among them re-exports one hop, the packages imported — laid into one `survey-<source>` turn under `survey.md` through `emery_sdk::survey::surfaces` (`survey::model`), the manifest and the modules that locate a surface laid whole, where the model names each surface at the lines that register or declare it and the stem its ids lead with. Code holds the answer to the tree — no surface under the bootstrap's `start`, every module the facts locate a surface in reached by a named surface or listed `unreached`, a finding otherwise and one correction round at a time — and derives the rest from the accepted anchors (`survey::surface::Derived::derive`): the registration, decorator, or export whole where the survey cited a line of it; the stem the code spells there — a route's resource under its mount or its controller's prefix, a literal's first word, and for `python` a management command's file stem — in place of the survey's where it spells one, the survey's standing where it spells none; what tells the surface from the others under its stem (the handler handed by name, else the verb and the path past the resource, the method's or the export's name, and the nearest segment of the entry's path where two are still alike); a class's decorated or public methods, an id apiece; the caller's `start` from the bootstrap; and the import closure each reaches (the bootstrap's stopping at every other surface's entry and reaching what each stopped entry constructs — its class fields' types, its module-level bindings' initializers; a registration's or a decorated method's reaching what its class references; a per-stem seam whose modules import what the resolver cannot follow, or load a module by a computed name, laying the rest of the tree after its closure, and the `.json` files a seam's modules import — for `python`, the data files its modules name by a literal path — laid as its data files, where a `criterion` may cite a value: after the modules for `typescript`; for `python`, a small one directly after the first module naming it and a large one after them all), so two runs that accept the same anchors open the same turns; each seam's text lays what its modules spell — the boundaries, the packages and the calls made through them, the decision points (guards, switches, conditionals, throws, catches, timers) a requirement anchors at, and the behaviours the tree's tests state. A survey never mines and chooses each seam — one `emery_sdk::Seam { text, files, stems, anchors }`, each field narrowing the turn and an empty one leaving it open: `text` leads the turn (a surface, its entry, its stem, the id its requirements lead with, and the modules it reaches — and, for `typescript` and `python`, the boundaries the seam's modules spell as values, the packages they import, and the calls they make through them — with the standing instructions after; its first line labels the seam in the log); `files` are the files to mine beneath the root — laid into the turn whole, every line numbered, when they fit within `emery_sdk::INLINE_BYTES` together, listed otherwise, and held to as the files a `path` may anchor in — and empty mines the whole lend; `stems` are the stems the seam's `requirement` and `criterion` ids must lead with, which the SDK's `check` holds every id to; `anchors` are the spans, in the claim `path` grammar, where the survey found a behaviour can start or its result is decided — for `typescript`, every decision point, every `return` of a value, the head of every function and method, every call through a package, every boundary and every line applying a constant-named one, every step a function takes into the tree — a call for its effect alone or one it awaits — and each surface's own lines, never a test's or a data file's — which the SDK holds every `requirement`'s `path` to, so one at a line that only wires comes back to re-anchor or drop, and empty holds it to none (a tree with no surface); `Seam::whole()`, `Seam::files(..)`, `Seam::note(..)`, and `Seam::anchors(..)` build the one-field shapes, and every seam of a workspace is lent the root. It refuses unusable input with `bad_request!` — a tree with no production module — and nothing else: a tree the survey names no surface in is mined under a mechanical cut (within the budget, one seam over every module under the manifest's or the root directory's name as its stem; past it, one seam per top-level directory, the root's own modules joined to the first), told that no surface was found and to read the code as a library is read. An inline value and a tree a mechanical cut leaves no finer than itself are one `Seam::whole()`; a kept tree within `INLINE_BYTES` (the adapter sums the texts it parsed) is one seam over its modules as `files`; a larger tree is one seam per stem, each carrying the surfaces under it and the union of their closures. `typescript` reads the tree's own tests (`*.test.*`, `*.spec.*`, `test/`, `tests/`, `__tests__/`, `.feature` files) and `python` its own (`test_*.py`, `*_test.py`, `tests.py`, modules under `test/`, `tests/`, `testing/`, `__tests__/`, `features/`, `.feature` files; a test's names and docstrings, a feature's scenarios) as stated behaviour, never as modules to mine: each case's or scenario's title is listed at its line under the seam whose files its imports resolve into, appended to that seam's `files` after the sources, and the prompt holds a test to be read and never anchored — a behaviour the laid code confirms is claimed at the code, one it does not hold is not invented. A survey is a plain fn over the input — all it reads — called from `extract` as `let seams = survey::survey(ctx.input)?;`, or, where the source's surfaces are the model's to name, code that reads the input (`survey::prepare`), puts the one survey turn (`survey::model::surfaces(ctx, PROSE, &prepared).await?`), and cuts the seams from what it derived (`survey::seams`); an inline value is never surveyed by the model. What a survey decides by code alone is asserted with no turn scripted for it; what it derives from the anchors the model names is asserted through a scripted `Inventory`. The crate lists its prose as `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its root — every document of the crate's `prose/` tree, each named from `src/lib.rs` the way `include_str!` names a file and embedded as it embeds one, and tabled by what follows its `prose/` segment (`extract.md`, the path `read_doc` and `check` know it by) — and the guest hands `PROSE` to `extract`. The references every adapter shares — the claim `id` grammar, `path` anchors, the skip roots, the fail-closed gate, and the `specify` pipeline — are the SDK's, not this repository's: `emery_sdk::RUNTIME` embeds them as `claims.md` and `reconciliation.md`, `read_doc` answers them after the adapter's own table, and a prompt at its `prose/` root links them as `claims.md` without any adapter listing them. The list is the crate's, not the guest's, because the root `tests/prose.rs` holds it to the tree, and to the prompts the SDK puts to the model (`extract.md`; `survey.md` too where the survey puts a turn), with `emery_sdk::check`, `emery_sdk::RUNTIME` as the imports: a document under `prose/` the list leaves out, a path listed twice, a relative link neither a listed document nor a runtime reference answers, a listed document no prompt reaches through those links, or a listed document at a runtime reference's path fails that suite, while a listed document the tree lacks fails the build at the list. There is no adapter error type: `emery_sdk::Error` is omnia's, and the WIT `error` variant is lowered and lifted inside the contract crate alone.
- Identity is the crate's version and its `emery:<name>@<semver>` package; resolve-time metadata is the component's `metadata` export. There is no manifest file.
- An adapter's dependencies are `emery-sdk` and the pure-Rust parser its source demands — pinned exactly while it is pre-1.0, scoped to `wasm32` so the native `rlib` the root suite reads carries none of it, and confined to the one module that parses (`typescript`'s and `python`'s `survey/parse/walk.rs`) so the rest of the survey reads the adapter's own types; never a `build.rs`, a C dependency, or a crate that reaches past WASI.
- Adapters never read the revision store or take lifecycle authority. Preserve gaps as `[unknown]`; keep claims platform-neutral.
- `prose/extract.md` is the one extraction pass: at most 800 non-blank lines, with a `## Worked example` JSON fence that parses as the SDK's `Evidence` (claims alone — the kind of source is the adapter's metadata, never the answer's) and passes the claim gate — `tests/prose.rs` enforces both. Where an adapter has the model name its surfaces, `prose/survey.md` is the one survey prompt, under the same cap, with a `## Worked example` JSON fence that parses as the SDK's `Inventory`, every anchor in the `path` grammar and every stem kebab-case — `tests/prose.rs` enforces those the same way. There is no third prompt: what a survey lays into a turn — the facts it read for the survey, the seam's `text` for the extraction — the prompt describes under its inputs, so the model is told how to read what code found, never how to find it. Every document under `prose/references/examples/` other than `README.md` is a worked example: its `## Evidence` JSON fence parses as `Evidence` and passes the gate, enforced the same way. References are written for the model in the adapter's current contract — what to read, which claims to emit — never addressed to a contributor. References are linked, never inlined, and every link names a document in `PROSE` or one of the SDK's runtime references (`claims.md`, `reconciliation.md`, from a prompt at the `prose/` root) — a directory or an unlisted file is unreadable through `read_doc`, and `tests/prose.rs` refuses it — and every document in `PROSE` is reached from a prompt by those links, or `tests/prose.rs` refuses that too: what nothing links is embedded and never read. A rule the SDK's references state is linked, never restated. Contributor guidance never goes in the embedded corpus.
- Do not commit built `.wasm` artifacts.

## Code style

The engine repository's ([`augentic/emery` AGENTS.md § Code style](https://github.com/augentic/emery/blob/main/AGENTS.md)): clippy under the shared `[workspace.lints]` in `Cargo.toml` and the guest deny-list in `clippy.toml`, plus nightly rustfmt (`make fmt`), are the gate; beyond them and the engine's standing rules, match the surrounding code. `#[expect(lint, reason = "…")]` at the smallest scope, never `#[allow]`. Comments follow the engine's rules in full: `///` on the public API only — in an adapter, the crate's `//!` and `PROSE`, since `survey` is private — a `//` on a private item only for a constraint, a why, or an invariant its name and signature do not say, in-body `//` as lowercase section headers, no match-arm labels, no history.

An adapter crate's `//!` docs state the source it accepts, how that source is divided for extraction, and any refusal visible to a caller — not the `wasm32` module layout, the guest-macro wiring, or how `PROSE` is checked.

A fn over one of the survey's types is that type's method, as the engine's rule has it. `Tree::read`, `Module::parse`, `Surface::start`, `Derived::derive`, and the `Lead` cuts construct; `Tree::handed`, `Module::declared_at`, and `Decorated::registering` look up and decide; `model::Located` and `survey::Lead` carry what their methods would otherwise thread through every call, and a policy list such as the decorators that shape a handler sits in `parse.rs` beside the type whose method reads it. A rule `surface` applies to a `Module` (`export_at`, `tells_apart`) stays its free fn, as does `unique`, pure over lists. What is pure over strings and reads no `Module` is the SDK's, never an adapter's copy: `emery_sdk::kebab`, `survey::Lines`, `survey::resolve::{Target, normalize}`, the route and literal stems under `survey::route`, and the `.feature` reader and stated-behaviours section under `survey::tests`. The one per-language input to the route rules is the adapter's `const SPELLING: route::Spelling` in `surface.rs`, and the one to `tests::stated` is `skeleton::DESCRIBED`.

## Testing

- An adapter's one contract is the `source-adapter` world, so what it decides is asserted through it: the root `tests/source.rs` runs the built component under the omnia runtime over a scripted host model and reads what the host sees. A workspace `extract` opens one completion per seam the survey chose — the strict script consumes exactly that many — each under the embedded `extract.md` and carrying the seam's data: the files a seam lists, the brief `intent` read through the mount, the surface lines, boundaries, and packages `typescript` and `python` lay (the adapter's own lines, never the SDK's brief text). Where the survey puts a turn, that turn opens first, under the embedded `survey.md` with the workspace lent and the survey schema, and the script answers it with an `Inventory` — the `inventory(..)` helper's surfaces and `unreached` — before the seam answers, one `Seen` per correction round where a finding sends the answer back, its `check` exchange recorded as the round's outcome; the scenario asserts what code derived from the anchors it scripted (the stems, ids, methods, closures, and notes the seams' briefs carry) and the facts the survey turn laid, never the answer's own words back; a refusal runs the driver's `refused <code> [<value>]` mode, lifting to its omnia class with no turn spent past it; what an adapter joins to the answer beyond the model's claims — `typescript`'s and `python`'s parsed `type` claims — runs the driver's `types <name>..` mode, which asserts the names and `#L` anchors the host sees over a workspace, then the unanchored ones over an inline value. An adapter has no tests of its own and no dev dependencies. Never pin prompt phrases; prompt quality is the live eval's.
- Root `tests/`: every shipped component, the boundary, and the corpus. `foreach_adapter!` and `foreach_probe!` make a new adapter or probe a compile error until `source.rs`, `prose.rs`, or `probe.rs` names it; that test carries its adapter's or program's name (`intent`, `probe_echo`), and an adapter's further scenarios are `<name>_<scenario>` (`documentation_directories`, `intent_empty_brief`). `prose.rs` runs `emery_sdk::check(<name>::PROSE, ..)` over the adapter's tree and the prompts it names, then the prompt checks, so a new adapter is also a root dev-dependency, and a guest package the wasm32 lint pass names (`WASM32_PACKAGES` in `mise.toml`, `wasm-packages` in `.github/workflows/ci.yaml`).
- What the SDK does for every adapter (the request shape, the reference tools, the lend, the claim gate's repair and spent-rounds refusal, the check of every anchor and id against its seam) is asserted once in the SDK's own suite and once under the runtime over the `gated` probe — never per adapter; an adapter's tracing follows its guest environment's `RUST_LOG`, which the runtime sets from the run's one level — command mode's `info` under the support's `deployment()`, which names no `Deployment::level`, as under a bare run of the shipped `emery` runtime — and that the SDK's `source_adapter_extract` boundary span exports under command mode's default filter alongside the adapter's own spans is asserted once, over the `telemetry` probe. The host property the SDK's fan-out rests on — the completions one guest issues together are pending together — is guarded once, over the `fanout` probe behind the support's `Barrier` model; the one the engine's fan-out over sources rests on — the link dispatches one caller issues together run together — once more, over the same probe in the driver's `together` mode.
- Always `cargo nextest`, and `--workspace` from the root as `make test` and CI do; every suite is the root package's today, so `cargo nextest run -p emery-adapters` runs the same tests.
- The guest side (`crates/test-programs/programs/`, the adapters' `survey` and `guest` modules) is `cfg(target_arch = "wasm32")`, which native clippy compiles to nothing, so `make lint` runs the shared `lint-wasm` pass — clippy over every lib, bin and example (never tests or benches) of the guest packages for `wasm32-wasip2`, the adapters and `test-programs` as `WASM32_PACKAGES` in `mise.toml` and `wasm-packages` in `.github/workflows/ci.yaml` name them, since the root package and the `evals` harness are native — over it (the command below); a new adapter is named in both lists; `make test` compiles it through the component build alone.

## Commands

All from the repository root through `make` ([`Makefile`](Makefile) → mise):

The tasks are the shared [`augentic/.github`](https://github.com/augentic/.github) `mise/rust.toml`, pinned in [`mise.toml`](mise.toml) to the same tag the workflows under `.github/workflows/` use; bump both together. `publish` is the one local task (it shadows the shared crates.io dry run: this train ships to GHCR).

```bash
make ci                              # exactly the CI jobs: fmt-check + lint + test + test-docs + docs + vet + deny — run before committing
make check                           # local advisories: audit + fmt (rewrites) + lint + outdated + deps
make test                            # cargo nextest run --locked --workspace --all-features
cargo nextest run -p emery-adapters --test source   # the shipped components alone
cargo run -p evals -- [case..]   # the graded live eval over the shipped emery binary; operator-invoked, never CI
make lint                            # lint-host (cargo clippy --workspace --all-targets --all-features, then cargo hack --each-feature), then lint-wasm (the same over every lib, bin and example of the guest packages for wasm32-wasip2 — never tests)
cargo clippy -p documentation -p intent -p typescript -p python -p test-programs --lib --bins --examples --all-features --target wasm32-wasip2 -- -D warnings   # the guest side alone; the first command of lint-wasm
cargo build -p <name> --target wasm32-wasip2 --release   # one component
cargo build --workspace --target wasm32-wasip2 --release   # every component
make publish <name>                  # push one built component to its GHCR tag
make vet-regen                       # regenerate cargo-vet imports/exemptions/unpublished, then vet
make sweep                           # drop target/ artifacts untouched for a week
```

If `make ci` cannot run, say exactly which narrower checks ran and why.

# Emery Adapters — Agent Instructions

Emery's first-party **source adapters** and **target adapters**. Each `adapters/<kind>` is one crate shipping as one WebAssembly component exporting one world of the `emery:adapter` WIT package: `source-adapter` (`metadata`, `extract(SourceInput) -> Evidence`) or `target-adapter` (`metadata` (the merge rules), `run(task)` over `init` / `build(slice)` / `verify`). `emery:<kind>` is crate `emery-<kind>` under `adapters/<kind>`; the tracing target and the wasm artifact are that name with the hyphen as an underscore (`emery_typescript`). The contract, vocabulary, and coding standards are the engine repository's ([`augentic/emery` AGENTS.md](https://github.com/augentic/emery/blob/main/AGENTS.md)); this repository owns extraction and build behaviour and prose. The v1 tree is archived at git tag `v1`.

## Git

Never `git commit`, `git push`, open or close a pull request, or delete a branch — in this repository or in any sibling checkout — unless the maintainer lifts this for the session, explicitly and for named work. Leave every change uncommitted in the working tree; the maintainer reviews and commits. No plan or to-do list carries a commit, push, or PR step, and an instruction to complete every step does not override this.

## Invariants

- A source adapter is a guest of the `source-adapter` world, written as every omnia guest is: `src/lib.rs` declares `pub struct Adapter;`, implements `emery_sdk::SourceAdapter` on it, and, last and under `cfg(target_arch = "wasm32")` alone, invokes `emery_sdk::export_source!(Adapter)` — the one macro, in the shape of `wit-bindgen`'s `export!(T)`; no adapter names a binding. The struct, its impl, and the `survey` it calls are native code, so the `rlib` the root suite reads carries the adapter whole and the export alone is the component's. `fn metadata() -> Metadata` declares the `kind` of source it reads, which the engine ranks the source by before any extract, and no answer carries it. `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>` is the crate's `survey` for the seams, then `emery_sdk::extract(ctx, PROSE, &seams).await`, then only what the survey read from the source itself joined to the answer (`typescript` and `python` hand the answer to `Survey::join`, which puts the `type` claims copied from the exported declarations in place of any the model answered — a class field initialised by a table of literals, names, or member paths with at least one entry, never a call, function, or spread, carries its declaration whole in `Member::table`; a module-level name bound to such a table carries its statement whole in `BindingKind::Value::table`, `typescript` leading it with the declaration's keyword; an empty object or dict is none) — so every model call goes through the SDK, one per seam and, for `typescript` and `python`, one survey turn per workspace before them, and no claim an adapter adds comes from a turn. The `Context` is the call: the adapter addressed, the input, and the model every turn is put to; no adapter names a backend, and the survey touches the model only through `emery_sdk::survey::seams` or `surfaces`.
- The adapter's survey inspects its source the way that source demands and owns the choice of seams where the source alone decides the cut. `emery_sdk::workspace::list(root, keep)` is only physical traversal, asking `keep` about each offered `Entry`. `documentation` reads every listed file that reads as text into a document with its outline (`survey/structure.rs`: front matter, fences, ATX and setext headings, list items, table rows, blockquotes, Gherkin headings and steps), and falls to cutting the listing by top-level directory (a directory of more than sixteen files once more by its subdirectories) only where the survey names no subject or the tree holds no document; `intent` uses it only to validate and read its one-file carrier. `typescript` and `python` read their trees with a parser (oxc; ruff's) into the SDK's `survey::code::Tree`, every kept module parsed through `Parsed::read` over the keep's `Listing` and the tree settled through the adapter's `Recogniser` (`survey/surface.rs`), which answers what its language alone decides: where each import leads (`resolve.rs`: a module, a package, a data file, `Target::Skipped` for a test module the keep set aside, else unresolved) and what the manifest declares; what a test states; the bootstrap (the first module the manifest names, or the conventional entry; for `python` a console script's target, a `__main__` guard, or an application constructed at module level); whether an argument is a handler (for `python`, a class too — a viewset on a router — never one handed to a package's own function or constructor) and the class a registration hands; where blueprints and routers are mounted; which classes declare data alone; and what the code says at an accepted anchor (`derive`, the `at_*` rules), the surface's typed `trigger` among it — `Trigger::Http` through `Route::parse` over the mount and the literal where the registration's verb is one HTTP method (`typed_route`), `Trigger::Message` over the literal where its method or decorator subscribes a handler by name (`typed_message`: `typescript`'s dialect listeners and `SUBSCRIBING`, `python`'s `SUBSCRIBING`; a lifecycle or connection event, a stream's payload event, and a task none), neither otherwise — which the SDK carries as the surface's `contract` claim. The SDK's `seams` owns the rest (the facts, the one `survey-<source>` turn where the model names each surface at the lines that register or declare it and the stem its ids lead with, the gate over the answer, `derive` from the accepted anchors so two runs accepting the same anchors open the same turns, the cut, the briefs, the copied `type` claims); an upstream client, a secret retriever, or a broker or store gateway the bootstrap constructs is a mechanism reached through the surface that uses it, so it lands in `start`'s closure and the design, never as a surface.
- A survey never mines: it chooses each seam, one `emery_sdk::Seam { text, files, stems, anchors, lexicon }`, each field narrowing the turn and an empty one leaving it open (the engine's `crates/sdk` row states them), and every seam of a workspace is lent the root. `anchors` are the spans where the survey found a behaviour can start or its result is decided — every decision point, `return`, function head, call through a package, boundary, and step into the tree, and each surface's own lines, never a test's or a data file's. `lexicon` is the fixed names by default (an adapter's own seams leave it `..Seam::default()`) and `Lexicon::from_packages` over the seam's imports for `typescript` and `python`. It refuses unusable input with `bad_request!` — a tree with no production module — and nothing else: a tree the survey names no surface in is mined under the SDK's mechanical cut (one seam under the manifest's or root directory's name within the budget, one per top-level directory past it), told that no surface was found and to read the code as a library is read. An inline value, and a tree a mechanical cut leaves no finer than itself, are one `Seam::whole()`; a kept tree within `INLINE_BYTES` is one seam over its modules as `files`; a larger tree is one seam per stem, each carrying the surfaces under it and the union of their closures. `typescript` reads the tree's own tests (`*.test.*`, `*.spec.*`, `test/`, `tests/`, `__tests__/`, `.feature` files) and `python` its own (`test_*.py`, `*_test.py`, `tests.py`, modules under `test/`, `tests/`, `testing/`, `__tests__/`, `features/`, `.feature` files) as stated behaviour, never as modules to mine: each case's or scenario's title is listed at its line under the seam whose files its imports resolve into, appended to that seam's `files` after the sources, and the prompt holds a test to be read and never anchored. A survey is a plain fn over the input, called as `survey::survey(ctx.input)?`, or, where the surfaces are the model's to name, one `async fn` over the `Context`, called as `survey::survey(ctx).await?`; an inline value is never surveyed by the model. `documentation` is the one adapter whose surfaces are the model's to name over no parsed tree: its survey puts the one `survey-<source>` turn through `emery_sdk::survey::surfaces` itself — the facts each document in path order with its length, headings at their lines, and what its body holds, the documents inlined whole; the `check` that every document is a subject's entry or listed `unreached` and no two subjects anchor at one line — and derives the rest by code: each subject's span (from its anchor to the line before the next subject's in its document, else the end, the preamble folded into the first), the id its claims lead with (the stem alone for the one subject under it, else the stem and a slug from its heading, name, or file), and the cut (one seam over every subject's document within `INLINE_BYTES`, held to every stem, one per stem past it, each told the other stems are other calls' and the `unreached` documents are context and never a `path`); a survey naming no subject falls to the directory cut. What a survey decides by code alone is asserted with no turn scripted; what it derives from the anchors the model names is asserted through a scripted `Inventory`.
- The crate lists its prose as `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its root — every document of the crate's `prose/` tree, each named from `src/lib.rs` as `include_str!` names a file — and the guest hands `PROSE` to `extract`. The list is the crate's because the root `tests/prose.rs` holds it to the tree and to the prompts the SDK puts (`extract.md`; `survey.md` where a survey turn is put) with `emery_sdk::check`, `emery_sdk::RUNTIME` as the imports, while a listed document the tree lacks fails the build at the list. There is no adapter error type: `emery_sdk::Error` is omnia's, and the WIT `error` variant is lowered and lifted inside the contract crate alone.
- A target adapter is a guest of the `target-adapter` world, written as a source adapter is: `pub struct Adapter;` implementing `emery_sdk::target::TargetAdapter` — `fn metadata() -> Metadata` (`Metadata::default()` when it declares neither): `rules`, the rules the engine merges every slice under, each built through the `const fn` `MergeRule::union` / `ours` / `theirs` over a `&'static str` glob, a path the rules leave conflicted the engine's to resolve with the model; where a build lands is the operator's `[target] repository` to say, never the adapter's, since its init scaffolds only what a tree lacks; `grants`, what the model's worker reaches beyond the lent tree for the toolchain the prompts run — one `Grant { egress, read, env }` per program, a private `const` spelled as that program's own documentation states its reach, none by default — which the SDK unites and puts with every build and verify turn as `grants.worker`, refusing a malformed one as `server_error` before any turn; and `async fn run<P: Model>(task: target::Task<'_, P>) -> Result<Outcome, Error>`, one match over the three tasks: `Task::Init(ctx)` (no model) the adapter's own code scaffolding the files of its layout the tree lacks — `create_new`, a held file left, a directory or a link at a file's path `bad_request` — answering `Outcome::Initialised`, put once per repository before any slice, the engine sealing what it scaffolded as the `Initialise` commit every slice builds over; `Task::Build(ctx)` `emery_sdk::target::build(&ctx, PROSE, check).await.map(Outcome::Built)` over a context carrying `scaffold` (`ctx.with_scaffold(..)` for an adapter whose own code scaffolded files into the working copy for the slice before the turn, `None` as lifted for one that scaffolds nothing, `node`) and `check`, the adapter's rule over the tree the turn wrote (`FnMut(&Report) -> Result<Vec<String>, Error>`, run over every candidate, its findings joining the SDK's gate under the one correction, its `Err` ending the turn); `Task::Verify(ctx)` `emery_sdk::target::verify(&ctx, PROSE, check).await.map(Outcome::Verified)`, `check` the same over `&Verdict` — and, last and under `cfg(target_arch = "wasm32")` alone, `emery_sdk::export_target!(Adapter)`. A target declares no kind and puts no survey: the init puts no turn, and every turn is the SDK's, one gated build turn per slice under `build.md` and one gated verify turn per wave under `verify.md`. What the adapter owns is the init, the skeleton, the prose, the rules, the grant, and one check per turn — a write before a turn, never after it, since what a turn leaves is what the engine seals. The grant is the adapter's to spell because the operator trusts the adapter by its digest already: the backend applies what this machine has (a `~/` root the home lacks is logged and granted nothing, a host is admitted at the proxy alone, a grant the backend refuses is `invalid-request`) and no variable of the operator's widens it, so a machine with its toolchain elsewhere runs a `-dev` build of the adapter whose `grants` name the root. `prose/build.md` and `prose/verify.md` are each at most 800 non-blank lines with a `## Worked example` JSON fence that parses as the SDK's `Report` (every `written` path one `beneath` accepts) and `Verdict` (passing `Verdict::findings`) respectively — `tests/prose.rs` enforces both — and every link names a document in `PROSE` or one of the SDK's runtime references, every document in `PROSE` reached from one of the two prompts. A rule the engine enforces (the report gate, the path rule, the head check) is stated once, in the SDK's brief, never restated in the prompt. One turn builds one slice whole, never one marker at a time: what an adapter's `Scaffold` derives from the typed contract is held by the write guard and `check`, while what it lays by heuristic — a number's integer or float guess, a pre-rendered status encoder, the reference passages selected — is a default the prompt leaves open to the scenarios and wire shapes, and `check` enforces the layout on the syntax tree rather than closing the turn's reads.
- Identity is the crate's version and its `emery:<kind>@<semver>` package, the crate named `emery-<kind>`; resolve-time metadata is the component's `metadata` export. There is no manifest file.
- An adapter's dependencies are `emery-sdk` and the pure-Rust parser its source demands — pinned exactly while pre-1.0, compiled for the host as for `wasm32` since the native `rlib` carries the survey, and confined to the one module that parses (`survey/parse/walk.rs`) so the rest of the survey reads the SDK's `survey::code` shapes and the adapter's `Module` over them — or, for a target whose layout another repository owns, that repository's crate as a git dependency (`omnia`'s `omnia-template`, `Cargo.lock` pinning the commit, `deny.toml` admitting the source), so the layout is compiled in from its one physical source and never copied, and the pure-Rust parser for the tree its checks read (`omnia`'s `syn`, the one reader of Rust in the crate, so a rule reads the syntax tree and never a line's indentation); never a `build.rs`, a C dependency, or a crate that reaches past WASI.
- Adapters never read the revision store or take lifecycle authority. Preserve gaps as `[unknown]`; keep claims platform-neutral: a `requirement` or `criterion` states behaviour by the role a thing plays and names no technology — the SDK returns one that does, or a survey stem that does, to the model to correct — and the technology reaches the design through a `call` or `excerpt` from a code source (`typescript`, `python`) and a `decision` from a prose source (`intent`, `documentation`): a directive or passage that prescribes a technology is a `decision` verbatim and the behaviour it governs a `requirement` by role, so a brief saying `publish each order event to Kafka` is two claims. A target reads the technology behind each role from the design's `## APIs and integrations`, never from the specification.
- `prose/extract.md` is the one extraction pass: at most 800 non-blank lines, with a `## Worked example` JSON fence that parses as the SDK's `Evidence` (claims alone — the kind of source is the adapter's metadata) and passes the claim gate — `tests/prose.rs` enforces both — and whose `requirement`, `criterion`, and `retire` claims name no technology of the SDK's `Lexicon`. It states the technology rule in the adapter's own terms and links `claims.md` for the rule itself: a code adapter's id convention carves the technology out of the source's own name for a behaviour (`start.require-brokers`, not `start.require-kafka-brokers`) and its `start` bullet claims the bootstrap for what those the program serves observe of it, the setting it refuses to run without among them, and leaves how it readies itself to the `excerpt` and the `call`; a prose adapter's kind table carries `decision` for the directive or passage that prescribes a technology — a `requirement` beside it only where the source states the behaviour itself, a passage whose whole content is the technology behind a behaviour the service already has being a `decision` alone, and a directive about a concept the service already has staying under that concept's stem — and `retire` for the one that withdraws a behaviour: its `id` the behaviour withdrawn in the subject's stem as the standing requirement or the other sources spell it, its `statement` the withdrawal by role, a `decision` beside it where the passage prescribes a technology too, never one for a behaviour the source is merely silent on, a passage saying a behaviour stays as it is a `requirement` restating it (classed `unchanged` by the engine), and one that withdraws and restates one behaviour a `requirement` alone under that behaviour's id. Where an adapter has the model name its surfaces, `prose/survey.md` is the one survey prompt, under the same cap, with a `## Worked example` JSON fence that parses as the SDK's `Inventory`, every anchor in the `path` grammar and every stem kebab-case — enforced the same way — and its stem convention names what a surface handles or does, never the technology it is reached through. There is no third prompt: what a survey lays into a turn the prompt describes under its inputs, so the model is told how to read what code found, never how to find it. Every document under `prose/references/examples/` other than `README.md` is a worked example whose `## Evidence` JSON fence parses as `Evidence` and passes the gate. References are written for the model in the adapter's current contract, never addressed to a contributor; linked, never inlined; every link names a document in `PROSE` or one of the SDK's runtime references (`claims.md`, `reconciliation.md`, from a prompt at the `prose/` root) — a directory or an unlisted file is unreadable through `read_doc` — and every document in `PROSE` is reached from a prompt by those links, or `tests/prose.rs` refuses it: what nothing links is embedded and never read. A rule the SDK's references state is linked, never restated. Contributor guidance never goes in the embedded corpus.
- Do not commit built `.wasm` artifacts.

## Code style

clippy (`make lint`) and nightly rustfmt (`make fmt`) are the style gate; beyond them and the rules below, match the surrounding code.

- Suppress a lint with `#[expect(lint, reason = "…")]` at the smallest scope, never `#[allow]`. The one standing exception is a `#![allow]` with its `reason` around generated bindings alone, whose lints are not the workspace's to expect.
- `<module>.rs` plus `<module>/<child>.rs`; `mod.rs` only under `tests/support/`.
- Visibility is an item's reach and nothing wider. An item is private unless another module reads it; a module's private items are visible to its children, so what only children read stays private whatever the module's own visibility. An item another module reads is `pub`, which a private module bounds to wherever that module is visible. `pub(crate)` only where `pub` would export the item from the crate — an item of a public module chain, or a method or field of a type the crate exports — and `clippy::redundant_pub_crate` refuses it anywhere else. Never `pub(super)` or `pub(in …)`.
- A fn over a type is that type's method, not a free fn taking it as its first argument, where the type's module declares the fn or the fn is a plain lookup or predicate on the type. A constructor is an associated fn. A policy `const` sits beside the type whose method reads it. Values several fns thread through every call become one struct whose methods they are. A fn stays free when it is pure over primitives and iterators, or when it is one module's rule applied to another module's type.

Comments follow the conventions `std`, `serde`, and `tokio` converge on: docs state the observable contract for the crate's user, never the body's mechanics.

- `///` goes on the public API only — the `pub` types, fns, fields, variants, and re-exports a user of the crate can reach — never on an `impl` block or a trait-impl method. An item the crate does not export takes none, whatever its `pub`: a private one, a `pub(crate)` one, a `pub` one in a private module. A clap field's `///` is its `--help` text. A doc opens with one summary sentence (about fifteen words, full stop), then a blank line, then short sentences and bullet lists. `# Examples` holds compiled doctests, for non-obvious usage only; `# Errors` names each class the caller matches on, linked; `# Panics` the rest. Every item mentioned is an intra-doc link. No mechanics, history, or migration notes. A `//!` says what a module is for, in the same shape.
- A private item takes a `//` only for what a senior developer would not see from its name and signature: a constraint, a why, an invariant. Most carry nothing. No restatements, match-arm labels, or body paraphrases.
- Inside a body, a `//` is a section header: lowercase, no full stop, above a blank-line-separated block, naming what the block achieves, so the headers read together outline the fn. A fn readable at a glance carries none, and a header never narrates the line beneath it. The one in-body explanation is `// HACK: …`, for a trick a senior would not see through.
- A test fn takes `//`, never `///`, and only for rationale its scenario name and assertions do not expose.
- No commented-out code.
- Every sentence earns its place and reads once: short plain sentences, one idea each; three or more things are a bullet list, not a colon-and-dash clause; no chained em-dashes, nested parentheticals, or semicolon runs; each fact has one home across `//!`, `///`, and `//`. A comment is as long as its why takes and no longer — concise is not dense, and readable is not verbose.

The guest deny-list in [`clippy.toml`](clippy.toml) is part of the gate beside the shared `[workspace.lints]`. In an adapter the public API is the crate's `//!`, `Adapter`, and `PROSE`, since `survey` is private.

An adapter crate's `//!` docs are one short paragraph after the summary sentence: for a source adapter, the source it accepts, how that source is divided for extraction, and any refusal visible to a caller; for a target adapter, the layout it initialises, how a slice lands in the tree, and the checks it runs — never the scaffold's, brief's, or check's mechanics, the module layout, the guest-macro wiring, or how `PROSE` is checked.

A fn over one of the survey's types is that type's method. The adapter's recogniser (`typescript::TypeScript`, `python::Python` in `survey/surface.rs`) holds the `Resolver` and the manifest reader, and its `Recogniser` impl is where the language's rules answer the SDK — `bootstrap`, `handler`, `mounts`, and `derive`, with the `at_*` rules a `derive` dispatches to, a method where one reads the recogniser, a free fn over the SDK's `Tree` otherwise, each reading a module's mount through `Tree::mount` rather than carrying the map. `Resolver::new` reads the SDK's `Parsed` tree for the modules, data files, and tests it answers. The module data model is the SDK's (`emery_sdk::survey::code`), and an adapter's `parse.rs` wraps its `Module` — `Deref` to the core, `Module::parse`, `settle_exports`, and `statements` as methods, the fields its language alone fills beside it (`python`'s `main_guard`, `tests`, `all`) — with `parse/walk.rs` the one producer; a rule of the adapter's over an SDK type (`python`'s `declares_data`) is a free fn in `parse.rs`. What a lookup reads of the language is data: the adapter's one `static DIALECT: emery_sdk::survey::Dialect` in `survey/dialect.rs`, passed to each lookup that reads one, with `DIALECT.route` the `Spelling` the route rules take and `python`'s `param_name` beside it as its one rule; a policy list `Dialect` does not carry (the bootstraps, the verbs, the mounting methods, the data bases) sits beside the fn that reads it. A rule `surface` applies to a `Module` (`export_at`, `decorated_at`) stays its free fn. What is pure over strings or lists and reads no `Module` is the SDK's (`kebab`, `unique`, `push_unique`, `survey::Lines`, `survey::resolve`, `survey::route`, `survey::tests`), never an adapter's copy, and so is what the SDK reads of the language for the facts and the briefs: a `Dialect` field, never a `const` of the adapter's.

## Testing

Tests drive the public boundary: a behaviour is asserted through what a user of the product or crate can reach, over scripted doubles rather than a live filesystem, network, or model, never through private internals. A suite below the root survives only for an independent library contract; a unit test only for a branch no public boundary reaches. A test fn names the scenario (`gen_spec`, `no_sources`), never the outcome. Scripted doubles are strict: script exactly the exchanges a run consumes.

- A target adapter's one contract is the `target-adapter` world, and its `Adapter` is that contract's native face: the root `tests/target.rs` calls `Adapter::run` over `Task::Init`, `Task::Build`, and `Task::Verify` through a `Shipped` handle per adapter (`OMNIA.init(&project)`, `NODE.built(..)`), each lending a scratch tree and, past the init, `omnia_test::guest::Scripted` as the model, with the `write_files` call, and an `edit_files` call where the adapter appends lines, scripted as `ToolCall`s through `.calling(0, ..)`, and asserts the `metadata()`'s `rules` in order, the grant its `grants` unite to (`Grant::union`) entry for entry with `Grant::findings` empty — never the grants themselves, so an adapter may regroup them while any widening shows — the init scaffolding each file of the layout the tree lacked byte for byte with no turn and leaving a held file, or a link at a file's path, as it stood, the skeleton the adapter scaffolds for a slice byte for byte under a turn that edits nothing (`omnia_scaffold`) and the brief's scaffold section naming its files and markers, the build turn opening under the embedded `build.md` with the tree lent and both tools declared, its brief carrying the slice, the report passing its gate and naming every file the calls wrote and none the init scaffolded, the verify turn under `verify.md` with both tools declared, each turn's `worker` the union of the adapter's `grants` as `Seen` records it, and a failed verdict carried as an answer. The gates, the brief's wording, and the tool are the SDK's, asserted once in its suite.
- A source adapter's one contract is the `source-adapter` world, and its `Adapter` is that contract's native face: the root `tests/source.rs` calls `Adapter::extract` over a `Context` — the adapter's name, a `SourceInput` over a scratch tree or an inline value, and `Scripted` as the model — through a `Shipped` handle per adapter (`TYPESCRIPT.run(..)`, `INTENT.refused(..)`), and reads the turns back from the script's `Seen` and `Exchange` records. A workspace `extract` opens one completion per seam the survey chose — the strict script consumes exactly that many — each under the embedded `extract.md` and carrying the seam's data (what the tree decided, never the SDK's standing prompt text). Where the survey puts a turn, that turn opens first, under the embedded `survey.md` with the workspace lent and the survey schema, and the script answers it with an `Inventory` (the `inventory(..)` helper) before the seam answers, one `Seen` per correction round where a finding sends the answer back; the scenario asserts what code derived from the anchors it scripted (the stems, ids, methods, closures, and notes the seams' briefs carry) and the facts the survey turn rendered, never the answer's own words back; a refusal is the `Err` the call answers, `refused(..)` holding it to `bad_request` with no turn spent past it; what an adapter joins beyond the model's claims (`typescript`'s and `python`'s parsed `type` claims) is read from the `Evidence` the call answers, `types(..)` asserting the names and `#L` anchors over a workspace, then the unanchored ones over an inline value. An adapter has no tests of its own and no dev dependencies. Never pin prompt phrases; prompt quality is the live eval's.
- What a native call cannot show is the component rung's, once per shipped component in `tests/component.rs`: the built component runs under the omnia runtime behind the `source_extract` or `builder_build` driver over a scripted host model, and the scenario asserts the export answered, the input lifted and the evidence lowered, the mount lent to every workspace turn and nothing to the inline value's, the embedded prompts leading the turns, a surface derived from the lent tree by the parser running as a guest, the metadata's merge rules lowered in order, the three tasks lifted in the engine's order and each answered by the outcome of its kind, the worker grant lowered onto both of a target's turns, and the files `write_files` wrote, the skeleton the adapter scaffolded and `edit_files` filled, and the layout the init scaffolded reaching the host's tree. The driver's modes are the bare run, `refused <code> [<value>]`, `echoed`, `together`, and `metadata <glob>=<strategy>..`, and nothing an adapter's own decision needs. An experiment arm is never a Cargo feature: `make test` runs the workspace under `--all-features`, which would turn it on in the native rlib while the component build keeps the default, so the two rungs would assert two behaviours; an arm is built from a worktree ([evals/README.md](evals/README.md)).
- Root `tests/`: every shipped component, the boundary, and the corpus. `foreach_adapter!`, `foreach_target!`, and `foreach_probe!` make a new source, target, or probe a compile error until `component.rs`, `prose.rs`, or `probe.rs` names it; that test carries its component's Cargo stem (`emery_intent`, `emery_node`, `probe_echo`), and an adapter's further scenarios are `<stem>_<scenario>` (`emery_documentation_subjects`, `emery_node_verify`). `prose.rs` runs `emery_sdk::check(<name>::PROSE, ..)` over the adapter's tree and the prompts it names, then the prompt checks, so a new adapter is also a root dev-dependency, and `WASM32_PACKAGES` in [`mise.toml`](mise.toml) must list it for `lint-wasm`.
- What the SDK does for every adapter (the request shape, the reference tools, the lend, the claim gate's repair and spent-rounds refusal, the check of every anchor and id against its seam) is asserted once in the SDK's own suite and once under the runtime over the `gated` probe — never per adapter; an adapter's tracing follows its guest environment's `RUST_LOG`, which the runtime sets from the run's one level (command mode's `info` under the support's `deployment()`), and that the SDK's `source_adapter_extract` boundary span exports alongside the adapter's own is asserted once, over the `telemetry` probe. The host property the SDK's fan-out rests on — the completions one guest issues together are pending together — is guarded once, over the `fanout` probe behind the support's `Barrier` model; the one the engine's fan-out over sources rests on — the link dispatches one caller issues together run together — once more, over the same probe in the driver's `together` mode.
- Always `cargo nextest`, and `--workspace` from the root as `make test` and CI do; every suite is the root package's today, so `cargo nextest run -p emery-adapters` runs the same tests.
- The guest side (`crates/test-programs/programs/`, and the export macro at the foot of each adapter's `src/lib.rs`) is `cfg(target_arch = "wasm32")`, which native clippy compiles to nothing, so `make lint` runs the shared `lint-wasm` pass — clippy over every lib, bin, and example (never tests or benches) of the packages `WASM32_PACKAGES` names in `mise.toml` for `wasm32-wasip2`; an adapter's `Adapter` and `survey` compile natively too, under `lint-host` and the root suite, and `make test` compiles the export through the component build alone.

## Commands

All from the repository root through `make` ([`Makefile`](Makefile) → mise). The tasks are the shared `mise/rust.toml` of [`augentic/toolkit`](https://github.com/augentic/toolkit), pinned in [`mise.toml`](mise.toml) to the tag every `uses:` under `.github/workflows/` names; bump both in one pull request when the pin moves.

```bash
make ci # exactly the CI jobs: fmt-check + lint + test + test-docs + docs + vet + deny — run before handing over
make check # local advisories: audit + fmt (rewrites) + lint + outdated + deps
make test # cargo nextest run --locked --workspace --all-features, under -Dwarnings
make lint # lint-host (cargo clippy --workspace --all-targets --all-features, then cargo hack --each-feature), then lint-wasm (the same over every lib, bin and example for wasm32-wasip2 — never tests)
make fmt # cargo +nightly fmt --all
make vet-regen # regenerate cargo-vet imports/exemptions/unpublished, then vet
make cov # cargo llvm-cov nextest --workspace --all-features --summary-only
make sweep # drop target/ artifacts untouched for a week
```

If `make ci` cannot run, say exactly why and which checks ran instead.

`publish` is the one local task (it shadows the shared crates.io dry run: this train ships to GHCR).

```bash
cargo nextest run -p emery-adapters --test source --test target # what the shipped adapters decide, natively
cargo nextest run -p emery-adapters --test component # the shipped components alone, under the runtime
cargo run -p evals -- [case..] # the graded live eval over the shipped emery binary; operator-invoked, never CI
cargo clippy -p emery-documentation -p emery-intent -p emery-typescript -p emery-python -p emery-node -p emery-omnia -p test-programs --lib --bins --examples --all-features --target wasm32-wasip2 -- -D warnings # the guest side alone; the first command of lint-wasm
cargo build -p emery-<kind> --target wasm32-wasip2 --release # one component, artifact emery_<kind>.wasm
cargo build --workspace --target wasm32-wasip2 --release # every component
make publish <name> # push one built component to its GHCR tag
```

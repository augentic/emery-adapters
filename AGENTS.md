# Emery Adapters — Agent Instructions

Emery's first-party **source adapters** and **target adapters**. Each `sources/<name>` is one crate shipping as one WebAssembly component that exports the `source-adapter` world of the `emery:adapter` WIT package: `metadata`, and `extract(SourceInput) -> Evidence` — a typed `SourceInput` (a name and a workspace or inline value) in, one Evidence document of typed claims out. Each `targets/<name>` is one crate shipping as one component that exports the `target-adapter` world: `metadata` (the merge rules), `build(Slice, workspace) -> Report`, and `verify(workspace) -> Verdict`. The contract, vocabulary, and coding standards are the engine repository's ([`augentic/emery` AGENTS.md](https://github.com/augentic/emery/blob/main/AGENTS.md)); this repository owns extraction behaviour and prose. The v1 tree is archived at git tag `v1`.

## Git

Never `git commit`, `git push`, open or close a pull request, or delete a branch — in this repository or in any sibling checkout — unless the maintainer lifts this for the session, explicitly and for named work. Leave every change uncommitted in the working tree; the maintainer reviews and commits. No plan or to-do list carries a commit, push, or PR step, and an instruction to complete every step does not override this.

## Map

| Path | Role |
| --- | --- |
| `sources/<name>/` | One adapter: `Cargo.toml` (`cdylib` + `rlib`, the `rlib` for the root suite's read of `PROSE` and `Adapter`; `[dependencies]` is `emery-sdk` and, where the source demands a parser, the pure-Rust crate that reads it (`typescript`: oxc; `python`: ruff's `ruff_python_parser`, `ruff_python_ast`, and `ruff_text_size`; each pinned exactly); no dev dependencies, no build dependencies, no `build.rs`); `src/lib.rs` = `mod survey;`, then `pub struct Adapter;` with `impl SourceAdapter for Adapter { const KIND .. async fn extract(ctx) .. }`, then `pub static PROSE: &[Doc] = emery_sdk::prose![..]` listing every document under `prose/`, and last, for `wasm32` alone, `emery_sdk::source_adapter!(Adapter);`; `src/survey.rs` = `pub fn survey` — a plain fn over the input, or, where the model names the surfaces, `pub async fn survey` over the `Context`, reading the input into the SDK's `Tree` and handing it to `emery_sdk::survey::seams` — declaring whatever the survey reads its source with as its children under `src/survey/` (`typescript` and `python` alike: `dialect.rs`, `parse.rs` and `parse/walk.rs`, `resolve.rs`, `surface.rs`, as Code style lays them out), the keep lists beside `survey` in `survey.rs`; `prose/{extract.md, references/}`, and `prose/survey.md` where a survey turn is put. No `tests/` of its own: what it decides is asserted by the root `tests/source.rs`, or `tests/component.rs` where the crate carries a feature arm |
| `targets/<name>/` | One target adapter: `Cargo.toml` (`cdylib` + `rlib`, `[dependencies]` `emery-sdk` alone; no `survey.rs`, since a target reads no source); `src/lib.rs` = the `//!`, `pub struct Adapter;` with `impl TargetAdapter for Adapter { const MERGE_RULES .. async fn build(ctx) .. async fn verify(ctx) .. }`, `pub static PROSE: &[Doc] = emery_sdk::prose![..]` listing every document under `prose/`, and last, for `wasm32` alone, `emery_sdk::target_adapter!(Adapter);`; `prose/build.md` and `prose/verify.md`, the two prompts the SDK puts, and `prose/references/` for what they link. `typescript-target` builds strict TypeScript on Node: one module per slice under `src/<stem>/`, one `export * as` line per module in `src/index.ts`, `node:test` tests under `test/<stem>.test.ts`, the manifests laid byte for byte from `references/layout.md`, `npm install` / `tsc --noEmit` / `npm test` as the loop and the verify, and the rules `package-lock.json` → `ours`, `src/index.ts` and `**/index.ts` → `union`, `package.json` unruled. No `tests/` of its own: the root `tests/target.rs` asserts it |
| `crates/test-programs/` | omnia's `test-programs` pattern: guest programs (`programs/source/extract.rs` drives the source boundary, `programs/builder/build.rs` the target boundary — under `builder/`, since a program under `programs/target/` would join the generated `target` group beside the shipped targets; `programs/probe/*` are fixture adapters) and the generated table of every built component |
| `tests/` | Root suites over every shipped adapter, on two rungs. Natively: `source.rs` calls each source adapter's `Adapter` as the component's export does, over a scratch tree and the SDK's scripted `Model`, and asserts what it decides — its seams, its refusals, its `type` claims — through the turns it opened and the evidence it answered; `target.rs` does the same for each target adapter, over a scratch tree the build writes through `write_files`, and asserts its merge rules, the build turn's lend and brief with the files the call wrote, and the verify turn's verdict; `prose.rs` holds each adapter's `PROSE` to its `prose/` tree and checks its prompts. Under the omnia runtime: `component.rs` drives every built component through its world once, over what a native call cannot show — the export, the lift and lower, the metadata, the lend resolved against the mount, the parser running as a guest — and holds `documentation`'s scenarios whole, since its `model-survey` arm is a Cargo feature the workspace's `--all-features` turns on in the native rlib while the component build keeps the default, the control; `probe.rs` drives the fixture adapters for the boundary itself (the runner the two share is `support/mod.rs`: `run` behind the source driver, `build` behind the target driver) |
| `examples/` | The `emery.toml` configs the shipped `emery` binary runs over the release-built components, pointing at eval case fixtures where a live walk needs them ([examples/README.md](examples/README.md)) |

The root `emery-adapters` package is tests only; it names each adapter crate, source or target, as a native dev-dependency so `tests/prose.rs` can read its `PROSE`. The one engine crate this workspace depends on, `emery-sdk`, is git-pinned in `[patch.crates-io]` beside `emery-prose`, which arrives beneath it and is patched only so both resolve from the same engine revision; the contract crate `emery-adapter` arrives beneath `emery-sdk` too, and neither is named by an adapter. Uncomment the path patches for sibling co-development and never commit them.

## Invariants

- An adapter is a guest of the `source-adapter` world, written the way every omnia guest is: `src/lib.rs` declares a unit struct, `pub struct Adapter;`, implements `emery_sdk::SourceAdapter` on it, and, last in the file and under `cfg(target_arch = "wasm32")` alone, invokes `emery_sdk::source_adapter!(Adapter)` over it — the one macro, in the shape of `wit-bindgen`'s `export!(T)`, which implements the world's `Guest` on a private type and exports it over the trait impl it names; no adapter names a binding. The struct, its impl, and the `survey` it calls are native code, so the `rlib` the root suite reads carries the adapter whole and the export alone is the component's. `const KIND: SourceKind` is the kind of source the adapter reads, which the macro answers the `metadata` export with through `emery_sdk::metadata` and the engine ranks the source by before any extract, and no answer carries it. `async fn extract<P: Model>(ctx: &Context<'_, P>) -> Result<Evidence, Error>` is the crate's `survey` for the seams, then `emery_sdk::extract(ctx, PROSE, &seams).await`, then only what the survey read from the source itself joined to the answer (`typescript` and `python` hand the answer to `Survey::join`, which puts the `type` claims they copied from the exported declarations in place of any the model answered) — so every model call goes through the SDK — one per seam, and for `typescript` and `python` one survey turn per workspace before them — joined into the source's one document, and no claim an adapter adds comes from a turn. The `Context` is the call — the adapter addressed, the input, and the model every turn is put to; the SDK's lift builds it from the WIT input and the host's model (`emery_sdk::Provider`) and lowers the outcome onto the WIT `evidence` and `error`, so no adapter names a backend, and the survey touches the model only through `emery_sdk::survey::seams`. The adapter's survey inspects its source in the way that source demands, and owns the choice of seams where the source alone decides the cut. `emery_sdk::workspace::list(root, keep)` is only physical workspace traversal: it prunes the engine's own files and asks `keep` about each offered `workspace::Entry` (`entry.hidden()`, `entry.name()`, and `entry.extension()` are the adapter's vocabulary for its policy); `documentation` cuts that listing by top-level directory, a directory of more than sixteen files once more by its subdirectories, while `intent` uses it only to validate and read its one-file carrier. `typescript` and `python` read their trees with a parser instead (oxc; ruff's) into the SDK's `survey::code::Tree`: every kept module parsed through `Parsed::read` over the keep's `Listing`, and the tree settled through the adapter's `Recogniser` (`survey/surface.rs`), which answers what its language alone decides — where each import leads (a module, a package, a data file, `Target::Skipped` for a test module the keep set aside, else unresolved) and what the manifest declares (`resolve.rs`); what a test states (`Module::statements`); the bootstrap, the first module the manifest names, or conventional entry, that runs when loaded (for `python`: a console script's target, a `__main__` guard, or an application constructed at module level, `app = create_app()`); whether an argument is a handler (for `python`, a class too — a viewset registered on a router — never one handed to a package's own function or constructor) and the class a registration hands; where blueprints and routers are mounted; which classes declare data alone; and what the code says at an anchor the survey accepted (`derive`, the `at_*` rules). The SDK's `emery_sdk::survey::seams(ctx, PROSE, &tree)` owns the rest and has the model name the surfaces: it lays the facts — the manifest, the bootstrap, every registration handed to a package outside a handler, every `def` or class under a package's registering decorator (lifecycle hooks set aside), what the entry modules export and what a barrel among them re-exports one hop, the packages imported — into one `survey-<source>` turn under `survey.md`, the manifest and the modules that locate a surface laid whole, where the model names each surface at the lines that register or declare it and the stem its ids lead with; holds the answer to the tree — no surface under the bootstrap's `start`, every module the facts locate a surface in reached by a named surface or listed `unreached`, a finding otherwise and one correction round at a time; derives the rest from the accepted anchors through the recogniser's `derive` — the registration, decorator, or export whole where the survey cited a line of it; the stem the code spells there in place of the survey's; what tells the surface from the others under its stem; a class's decorated or public methods, an id apiece; the caller's `start` from the bootstrap; and the import closure and data files each reaches, as the engine's `crates/sdk` row states them — so two runs that accept the same anchors open the same turns; cuts the seams; renders each brief from what its modules spell — the boundaries, the packages and the calls made through them, the decision points (guards, switches, conditionals, throws, catches, timers) a requirement anchors at, and the behaviours the tree's tests state; and copies the `type` claims of the reached modules. A survey never mines and chooses each seam — one `emery_sdk::Seam { text, files, stems, anchors }`, each field narrowing the turn and an empty one leaving it open: `text` leads the turn (a surface, its entry, its stem, the id its requirements lead with, and the modules it reaches — and, for `typescript` and `python`, the boundaries the seam's modules spell as values, the packages they import, and the calls they make through them — with the standing instructions after; its first line labels the seam in the log); `files` are the files to mine beneath the root — laid into the turn whole, every line numbered, when they fit within `emery_sdk::INLINE_BYTES` together, listed otherwise, and held to as the files a `path` may anchor in — and empty mines the whole lend; `stems` are the stems the seam's `requirement` and `criterion` ids must lead with, which the SDK's `check` holds every id to; `anchors` are the spans, in the claim `path` grammar, where the survey found a behaviour can start or its result is decided — every decision point, `return`, function head, call through a package, boundary, and step a function takes into the tree, and each surface's own lines, never a test's or a data file's — which the SDK holds every `requirement`'s `path` to, so one at a line that only wires comes back to re-anchor or drop, and empty holds it to none (a tree with no surface); `Seam::whole()`, `Seam::files(..)`, `Seam::note(..)`, and `Seam::anchors(..)` build the one-field shapes, and every seam of a workspace is lent the root. It refuses unusable input with `bad_request!` — a tree with no production module — and nothing else: a tree the survey names no surface in is mined under the SDK's mechanical cut (one seam under the manifest's or root directory's name within the budget, one per top-level directory past it), told that no surface was found and to read the code as a library is read. An inline value and a tree a mechanical cut leaves no finer than itself are one `Seam::whole()`; a kept tree within `INLINE_BYTES` (the SDK sums the texts the adapter parsed) is one seam over its modules as `files`; a larger tree is one seam per stem, each carrying the surfaces under it and the union of their closures. `typescript` reads the tree's own tests (`*.test.*`, `*.spec.*`, `test/`, `tests/`, `__tests__/`, `.feature` files) and `python` its own (`test_*.py`, `*_test.py`, `tests.py`, modules under `test/`, `tests/`, `testing/`, `__tests__/`, `features/`, `.feature` files; a test's names and docstrings, a feature's scenarios) as stated behaviour, never as modules to mine: each case's or scenario's title is listed at its line under the seam whose files its imports resolve into, appended to that seam's `files` after the sources, and the prompt holds a test to be read and never anchored — a behaviour the laid code confirms is claimed at the code, one it does not hold is not invented. A survey is a plain fn over the input — all it reads — called from `extract` as `let seams = survey::survey(ctx.input)?;`, or, where the source's surfaces are the model's to name, one `async fn` over the `Context`, called as `survey::survey(ctx).await?`, that reads the input into the SDK's tree and hands it to the SDK's one entry (`emery_sdk::survey::seams(ctx, PROSE, &tree).await`), which puts the survey turn and cuts the seams; an inline value is never surveyed by the model. What a survey decides by code alone is asserted with no turn scripted for it; what it derives from the anchors the model names is asserted through a scripted `Inventory`. The crate lists its prose as `pub static PROSE: &[Doc] = emery_sdk::prose!["../prose/extract.md", ..];` at its root — every document of the crate's `prose/` tree, each named from `src/lib.rs` as `include_str!` names a file and tabled by what follows its `prose/` segment (`extract.md`, the path `read_doc` and `check` know it by) — and the guest hands `PROSE` to `extract`. The list is the crate's, not the guest's, because the root `tests/prose.rs` holds it to the tree, and to the prompts the SDK puts to the model (`extract.md`; `survey.md` too where the survey puts a turn), with `emery_sdk::check`, `emery_sdk::RUNTIME` as the imports, while a listed document the tree lacks fails the build at the list. There is no adapter error type: `emery_sdk::Error` is omnia's, and the WIT `error` variant is lowered and lifted inside the contract crate alone.
- A target adapter is a guest of the `target-adapter` world, written as a source adapter is: `src/lib.rs` declares `pub struct Adapter;`, implements `emery_sdk::target::TargetAdapter` on it — `const MERGE_RULES: &'static [MergeRule]`, the rules the engine merges every slice under, which the macro answers `metadata` with through `emery_sdk::target::metadata`; `async fn build<P: Model>(ctx: &target::Context<'_, P>) -> Result<Report, Error>` as `emery_sdk::target::build(ctx, PROSE).await`; `async fn verify<P: Model>(ctx: &target::VerifyContext<'_, P>) -> Result<Verdict, Error>` as `emery_sdk::target::verify(ctx, PROSE).await` — and, last and under `cfg(target_arch = "wasm32")` alone, invokes `emery_sdk::target_adapter!(Adapter)` over it. A target declares no kind and puts no survey: every turn is the SDK's, one gated build turn per slice under the adapter's `build.md` (the slice's plan entry, specification cut, and whole design in the brief, the working copy lent writable and written through the turn's `write_files` tool, one or more files a call, the report gate and the tree as its check) and one gated verify turn per wave under `verify.md` (the integrated tree lent with the shell and no `write_files`, the verdict gate as its check). What the adapter owns is the prose and the rules: the layout a slice lands in, the checks the model runs through the shell before it reports, how two slices' writes to one path merge. `prose/build.md` and `prose/verify.md` are each at most 800 non-blank lines with a `## Worked example` JSON fence that parses as the SDK's `Report` (every `written` path one `beneath` accepts) and `Verdict` (passing `Verdict::findings`) respectively — `tests/prose.rs` enforces both — and every link names a document in `PROSE` or one of the SDK's runtime references, every document in `PROSE` reached from one of the two prompts. A rule the engine enforces (the report gate, the path rule, the head check) is stated once, in the SDK's brief, never restated in the prompt.
- Identity is the crate's version and its `emery:<name>@<semver>` package; resolve-time metadata is the component's `metadata` export. There is no manifest file.
- An adapter's dependencies are `emery-sdk` and the pure-Rust parser its source demands — pinned exactly while it is pre-1.0, compiled for the host as for `wasm32` since the native `rlib` the root suite reads carries the survey, and confined to the one module that parses (`typescript`'s and `python`'s `survey/parse/walk.rs`) so the rest of the survey reads the SDK's `survey::code` shapes and the adapter's `Module` over them; never a `build.rs`, a C dependency, or a crate that reaches past WASI.
- Adapters never read the revision store or take lifecycle authority. Preserve gaps as `[unknown]`; keep claims platform-neutral.
- `prose/extract.md` is the one extraction pass: at most 800 non-blank lines, with a `## Worked example` JSON fence that parses as the SDK's `Evidence` (claims alone — the kind of source is the adapter's metadata, never the answer's) and passes the claim gate — `tests/prose.rs` enforces both. Where an adapter has the model name its surfaces, `prose/survey.md` is the one survey prompt, under the same cap, with a `## Worked example` JSON fence that parses as the SDK's `Inventory`, every anchor in the `path` grammar and every stem kebab-case — `tests/prose.rs` enforces those the same way. There is no third prompt: what a survey lays into a turn — the facts it read for the survey, the seam's `text` for the extraction — the prompt describes under its inputs, so the model is told how to read what code found, never how to find it. Every document under `prose/references/examples/` other than `README.md` is a worked example: its `## Evidence` JSON fence parses as `Evidence` and passes the gate, enforced the same way. References are written for the model in the adapter's current contract — what to read, which claims to emit — never addressed to a contributor. References are linked, never inlined, and every link names a document in `PROSE` or one of the SDK's runtime references (`claims.md`, `reconciliation.md`, from a prompt at the `prose/` root) — a directory or an unlisted file is unreadable through `read_doc`, and `tests/prose.rs` refuses it — and every document in `PROSE` is reached from a prompt by those links, or `tests/prose.rs` refuses that too: what nothing links is embedded and never read. A rule the SDK's references state is linked, never restated. Contributor guidance never goes in the embedded corpus.
- Do not commit built `.wasm` artifacts.

## Code style

clippy (`make lint`) and nightly rustfmt (`make fmt`) are the style gate; beyond them and the rules below, match the surrounding code.

- Suppress a lint with `#[expect(lint, reason = "…")]` at the smallest scope, never `#[allow]`.
- `<module>.rs` plus `<module>/<child>.rs`; `mod.rs` only under `tests/support/`.
- A fn over a type is that type's method, not a free fn taking it as its first argument, where the type's module declares the fn or the fn is a plain lookup or predicate on the type. A constructor is an associated fn. A policy `const` sits beside the type whose method reads it. Values several fns thread through every call become one struct whose methods they are. A fn stays free when it is pure over primitives and iterators, or when it is one module's rule applied to another module's type.

Comments follow the conventions `std`, `serde`, and `tokio` converge on: docs state the observable contract for the crate's user, never the body's mechanics.

- `///` goes on the public API only — the `pub` types, fns, fields, variants, and re-exports a user of the crate can reach — never on a private or `pub(crate)` item, an `impl` block, or a trait-impl method. A clap field's `///` is its `--help` text. A doc opens with one summary sentence (about fifteen words, full stop), then a blank line, then short sentences and bullet lists. `# Examples` holds compiled doctests, for non-obvious usage only; `# Errors` names each class the caller matches on, linked; `# Panics` the rest. Every item mentioned is an intra-doc link. No mechanics, history, or migration notes. A `//!` says what a module is for, in the same shape.
- A private item takes a `//` only for what a senior developer would not see from its name and signature: a constraint, a why, an invariant. Most carry nothing. No restatements, match-arm labels, or body paraphrases.
- Inside a body, a `//` is a section header: lowercase, no full stop, above a blank-line-separated block, naming what the block achieves, so the headers read together outline the fn. A fn readable at a glance carries none, and a header never narrates the line beneath it. The one in-body explanation is `// HACK: …`, for a trick a senior would not see through.
- A test fn takes `//`, never `///`, and only for rationale its scenario name and assertions do not expose.
- No commented-out code.
- Every sentence earns its place and reads once: short plain sentences, one idea each; three or more things are a bullet list, not a colon-and-dash clause; no chained em-dashes, nested parentheticals, or semicolon runs; each fact has one home across `//!`, `///`, and `//`. A comment is as long as its why takes and no longer — concise is not dense, and readable is not verbose.

The guest deny-list in [`clippy.toml`](clippy.toml) is part of the gate beside the shared `[workspace.lints]`. In an adapter the public API is the crate's `//!`, `Adapter`, and `PROSE`, since `survey` is private.

An adapter crate's `//!` docs state the source it accepts, how that source is divided for extraction, and any refusal visible to a caller — not the module layout, the guest-macro wiring, or how `PROSE` is checked.

A fn over one of the survey's types is that type's method, as the rule above has it. The adapter's recogniser (`typescript::TypeScript`, `python::Python` in `survey/surface.rs`) holds the `Resolver` and the manifest reader, and its `Recogniser` impl is where the language's rules answer the SDK: `bootstrap`, `handler`, `mounts`, and `derive`, with the `at_*` rules a `derive` dispatches to — a method where one reads the recogniser, a free fn over the SDK's `Tree` otherwise, each reading a module's mount through `Tree::mount` rather than carrying the map. `Resolver::new` reads the SDK's `Parsed` tree for the modules, data files, and tests it answers. `Module::parse` constructs; `Module::declared_at` and `Decorated::registering` look up and decide; the SDK's `Tree` (`closure`, `reaches`, `receiver`, `registration_at`, `identify`) carries what the rules would otherwise thread through every call. The module data model is the SDK's (`emery_sdk::survey::code`: `Module` and its lookups, `Import`, `Export`, `Binding`, `Call`, `Decorated`, `ClassDecl`, `TypeDecl`, and the rest), and an adapter's `parse.rs` wraps its `Module` — `Deref` to the core, `Module::parse`, `settle_exports`, and `statements` as methods, the fields its language alone fills beside it (`python`'s `main_guard`, `tests`, `all`) — with `parse/walk.rs` the one producer; a rule of the adapter's over an SDK type (`python`'s `declares_data`) is a free fn in `parse.rs`. What a lookup reads of the language is data, not code: the adapter's one `static DIALECT: emery_sdk::survey::Dialect` in `survey/dialect.rs`, passed to each lookup that reads one, with `DIALECT.route` the `Spelling` the route rules take and `python`'s `param_name` beside it as its one rule; a policy list `Dialect` does not carry — the bootstraps, the verbs, the mounting methods, the data bases — sits beside the fn that reads it. A rule `surface` applies to a `Module` (`export_at`, `decorated_at`) stays its free fn. What is pure over strings or lists and reads no `Module` is the SDK's (`kebab`, `unique`, `push_unique`, `survey::Lines`, `survey::resolve`, `survey::route`, `survey::tests`), never an adapter's copy, and so is what the SDK reads of the language for the facts and the briefs: a `Dialect` field, never a `const` of the adapter's.

## Testing

Tests drive the public boundary: a behaviour is asserted through what a user of the product or crate can reach, over scripted doubles rather than a live filesystem, network, or model, never through private internals. A suite below the root survives only for an independent library contract; a unit test only for a branch no public boundary reaches. A test fn names the scenario (`gen_spec`, `no_sources`), never the outcome. Scripted doubles are strict: script exactly the exchanges a run consumes.

- A target adapter's one contract is the `target-adapter` world, and its `Adapter` is that contract's native face, so what it declares is asserted through it: the root `tests/target.rs` calls `Adapter::build` over a `target::Context` and `Adapter::verify` over a `VerifyContext`, each lending a scratch tree and `omnia_test::guest::Scripted` as the model, with the one `write_files` call scripted as a `ToolCall` through `.calling(0, ..)`, and asserts `MERGE_RULES` in order, the build turn opening under the embedded `build.md` with the tree lent and `write_files` declared, its brief carrying the slice, the report passing its gate and naming every file the call wrote, the tree holding each, the verify turn under `verify.md` with no `write_files`, and a failed verdict carried as an answer. The gates, the brief's wording, and the tool are the SDK's, asserted once in its suite.
- A source adapter's one contract is the `source-adapter` world, and its `Adapter` is that contract's native face, so what it decides is asserted through it: the root `tests/source.rs` calls `Adapter::extract` over a `Context` — the adapter's name, a `SourceInput` over a scratch tree or an inline value, and `Scripted` as the model — through a `Shipped` handle per adapter (`TYPESCRIPT.run(..)`, `INTENT.refused(..)`), and reads the turns back from the script's `Seen` and `Exchange` records, the same records the host's double keeps. A workspace `extract` opens one completion per seam the survey chose — the strict script consumes exactly that many — each under the embedded `extract.md` and carrying the seam's data: the files a seam lists, the brief `intent` read from the tree, the surface lines, boundaries, and packages the SDK lays for `typescript` and `python` from what their recognisers derived (what the tree decided, never the SDK's standing prompt text). Where the survey puts a turn, that turn opens first, under the embedded `survey.md` with the workspace lent and the survey schema, and the script answers it with an `Inventory` — the `inventory(..)` helper's surfaces and `unreached` — before the seam answers, one `Seen` per correction round where a finding sends the answer back, its `check` exchange recorded as the round's outcome; the scenario asserts what code derived from the anchors it scripted (the stems, ids, methods, closures, and notes the seams' briefs carry) and the facts the survey turn laid, never the answer's own words back; a refusal is the `Err` the call answers, `refused(..)` holding it to `bad_request` with no turn spent past it; what an adapter joins to the answer beyond the model's claims — `typescript`'s and `python`'s parsed `type` claims — is read from the `Evidence` the call answers, `types(..)` asserting the names and `#L` anchors over a workspace, then the unanchored ones over an inline value. An adapter has no tests of its own and no dev dependencies. Never pin prompt phrases; prompt quality is the live eval's.
- What a native call cannot show is the component rung's, once per shipped component in `tests/component.rs`: the built component runs under the omnia runtime behind the `source_extract` or `builder_build` driver over a scripted host model, and the scenario asserts the export answered, the input lifted and the evidence lowered, the mount lent to every workspace turn and nothing to the inline value's, the embedded prompts leading the turns, a surface derived from the lent tree by the parser running as a guest, the metadata's merge rules lowered in order, and the files `write_files` wrote reaching the host's tree. The driver's modes are the bare run, `refused <code> [<value>]`, `echoed`, `together`, and `rules <glob>=<strategy>..`, and nothing an adapter's own decision needs. An adapter whose experiment arm is a Cargo feature is asserted there whole, as `documentation` is: `make test` runs the workspace under `--all-features`, which turns the arm on in the native rlib, while the component build keeps the crate's default, the control.
- Root `tests/`: every shipped component, the boundary, and the corpus. `foreach_adapter!`, `foreach_target!`, and `foreach_probe!` make a new source, target, or probe a compile error until `component.rs`, `prose.rs`, or `probe.rs` names it; that test carries its adapter's or program's name (`intent`, `typescript_target`, `probe_echo`), and an adapter's further scenarios, in `component.rs` or the native suite that asserts it, are `<name>_<scenario>` (`documentation_directories`, `intent_empty_brief`, `typescript_target_verify`). `prose.rs` runs `emery_sdk::check(<name>::PROSE, ..)` over the adapter's tree and the prompts it names, then the prompt checks, so a new adapter is also a root dev-dependency, and `WASM32_PACKAGES` in [`mise.toml`](mise.toml) must list it for `lint-wasm`.
- What the SDK does for every adapter (the request shape, the reference tools, the lend, the claim gate's repair and spent-rounds refusal, the check of every anchor and id against its seam) is asserted once in the SDK's own suite and once under the runtime over the `gated` probe — never per adapter; an adapter's tracing follows its guest environment's `RUST_LOG`, which the runtime sets from the run's one level — command mode's `info` under the support's `deployment()`, which names no `Deployment::level`, as under a bare run of the shipped `emery` runtime — and that the SDK's `source_adapter_extract` boundary span exports under command mode's default filter alongside the adapter's own spans is asserted once, over the `telemetry` probe. The host property the SDK's fan-out rests on — the completions one guest issues together are pending together — is guarded once, over the `fanout` probe behind the support's `Barrier` model; the one the engine's fan-out over sources rests on — the link dispatches one caller issues together run together — once more, over the same probe in the driver's `together` mode.
- Always `cargo nextest`, and `--workspace` from the root as `make test` and CI do; every suite is the root package's today, so `cargo nextest run -p emery-adapters` runs the same tests.
- The guest side (`crates/test-programs/programs/`, and the export macro at the foot of each adapter's `src/lib.rs`) is `cfg(target_arch = "wasm32")`, which native clippy compiles to nothing, so `make lint` runs the shared `lint-wasm` pass — clippy over every lib, bin and example (never tests or benches) of the guest packages for `wasm32-wasip2`, the adapters and `test-programs` named in `WASM32_PACKAGES` in `mise.toml`, since the root package and the `evals` harness are native — over it (the command below); an adapter's `Adapter` and `survey` compile natively too, under `lint-host` and the root suite, and `make test` compiles the export through the component build alone.

## Commands

All from the repository root through `make` ([`Makefile`](Makefile) → mise). The tasks are the shared `mise/rust.toml` of [`augentic/toolkit`](https://github.com/augentic/toolkit), pinned in [`mise.toml`](mise.toml) to the tag every `uses:` under `.github/workflows/` names; bump both in one pull request when the pin moves.

```bash
make ci # exactly the CI jobs: fmt-check + lint + test + test-docs + docs + vet + deny — run before handing over
make check # local advisories: audit + fmt (rewrites) + lint + outdated + deps
make test # cargo nextest run --locked --workspace --all-features, under -Dwarnings
make lint # lint-host (cargo clippy --workspace --all-targets --all-features, then cargo hack --each-feature), then lint-wasm (the same over every lib, bin and example for wasm32-wasip2 — never tests)
make fmt # cargo +nightly fmt --all
make vet-regen # regenerate cargo-vet imports/exemptions/unpublished, then vet
make cov # cargo llvm-cov nextest --workspace --all-features --summary-only
make sweep # drop target/ artifacts untouched for a week
```

If `make ci` cannot run, say exactly why and which checks ran instead.

`publish` is the one local task (it shadows the shared crates.io dry run: this train ships to GHCR).

```bash
cargo nextest run -p emery-adapters --test source --test target # what the shipped adapters decide, natively
cargo nextest run -p emery-adapters --test component # the shipped components alone, under the runtime
cargo run -p evals -- [case..] # the graded live eval over the shipped emery binary; operator-invoked, never CI
cargo clippy -p documentation -p intent -p typescript -p python -p typescript-target -p test-programs --lib --bins --examples --all-features --target wasm32-wasip2 -- -D warnings # the guest side alone; the first command of lint-wasm
cargo build -p <name> --target wasm32-wasip2 --release # one component
cargo build --workspace --target wasm32-wasip2 --release # every component
make publish <name> # push one built component to its GHCR tag
```
